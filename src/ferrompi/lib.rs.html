1//! # ferrompi
2//!
3//! Safe, generic Rust bindings for MPI (Message Passing Interface).
4//!
5//! This crate wraps MPI functionality through a thin C layer.
6//!
7//! ## Capabilities
8//!
9//! - **Generic API**: All operations work with any [`MpiDatatype`] (`f32`, `f64`, `i32`, `i64`, `u8`, `u32`, `u64`)
10//! - **Blocking collectives**: barrier, broadcast, reduce, allreduce, gather, scatter, allgather,
11//!   alltoall, scan, exscan, reduce\_scatter\_block, plus V-variants (gatherv, scatterv, allgatherv, alltoallv)
12//! - **Nonblocking collectives**: all 15 `i`-prefixed variants, plus six in-place forms, created inside a [`scope`]
13//! - **Persistent collectives** (MPI 4.0, or Open MPI 5): `*_init` forms of every blocking collective,
14//!   plus six in-place forms, with [`PersistentRequest`] handles
15//! - **Large counts**: with an MPI 4.0 library, a count above `i32::MAX` uses MPI's `_c` call
16//!   (point-to-point, collectives including persistent ones, RMA); below
17//!   MPI 4.0 it returns [`Error::Mpi`] with class [`MpiErrorClass::Count`]. On such a library, a
18//!   matched message above `i32::MAX` bytes cannot be discarded by dropping its [`Message`], and
19//!   [`Message::mrecv`] tells MPI of at most `i32::MAX` elements of room. The V-collectives
20//!   (`gatherv`, `scatterv`, `allgatherv`, `alltoallv`, and their persistent forms), which take
21//!   counts as `i32` arrays, and every reduction with a user op, whose user function takes an
22//!   `int` length, return that error on every MPI version.
23//! - **Scalar and in-place variants**: `reduce_scalar`, `allreduce_scalar`, `reduce_inplace`,
24//!   `allreduce_inplace`, `scan_scalar`, `exscan_scalar`
25//! - **Point-to-point**: `send`, `recv`, `isend`, `irecv`, `sendrecv`, `probe`, `iprobe`, and the
26//!   matched probes `mprobe` and `improbe`, whose [`Message`] only its own `mrecv` can receive
27//! - **Persistent point-to-point**: `send_init`, `bsend_init`, `rsend_init`, `ssend_init`,
28//!   `recv_init` methods on [`Communicator`], each returning a [`PersistentRequest`]
29//! - **Communicator management**: `split`, `split_type`, `split_shared`, `duplicate`
30//! - **Group operations**: [`Group`] with incl/excl/union/intersection/difference,
31//!   [`RankRange`] for range constructors, [`GroupComparison`].
32//!
33//!   Note: [`Mpi::create_from_group`] needs MPI 4.0, or Open MPI 5.
34//! - **Custom datatypes**: [`CustomDatatype`]
35//!   (contiguous/vector/struct/resized) and [`StructField`]
36//!   for struct-type builders.
37//! - **User-defined reduction operations**: [`UserOp`] wraps `MPI_Op_create`
38//!   with safe closure storage and trampoline.
39//! - **RMA and shared-memory windows** (feature `rma`): `Win<T>` with
40//!   `WinFenceAssert`, `WinPscwAssert`, and closure epochs over
41//!   `ActiveEpoch` and `PassiveEpoch`; `Win::allocate_shared` for intra-node
42//!   shared memory; `WinView` for access to a window's memory.
43//! - **SLURM helpers** (feature `slurm`): Job topology queries via `slurm` module
44//! - **Rich error handling**: [`MpiErrorClass`] categorization with messages from the MPI runtime
45//!
46//! ## Supported Types
47//!
48//! All communication operations are generic over [`MpiDatatype`]:
49//! `f32`, `f64`, `i32`, `i64`, `u8`, `u32`, `u64`
50//!
51//! ## Quick Start
52//!
53//! ```no_run
54//! use ferrompi::{Mpi, ReduceOp};
55//!
56//! fn main() -> Result<(), ferrompi::Error> {
57//!     let mpi = Mpi::init()?;
58//!     let world = mpi.world();
59//!
60//!     let rank = world.rank();
61//!     let size = world.size();
62//!     println!("Hello from rank {} of {}", rank, size);
63//!
64//!     // Generic broadcast — works with any MpiDatatype
65//!     let mut data = vec![0.0f64; 100];
66//!     if rank == 0 {
67//!         data.fill(42.0);
68//!     }
69//!     world.broadcast(&mut data, 0)?;
70//!
71//!     // Generic all-reduce
72//!     let sum = world.allreduce_scalar(rank as f64, ReduceOp::Sum)?;
73//!     println!("Rank {rank}: sum of all ranks = {sum}");
74//!
75//!     Ok(())
76//! }
77//! ```
78//!
79//! ## Feature Flags
80//!
81//! | Feature | Description | Dependencies |
82//! |---------|-------------|--------------|
83//! | `rma`   | RMA and shared-memory windows (`Win`, epoch handles, views, RMA operations) | — |
84//! | `slurm` | The `slurm` module and `SlurmInfo` | — |
85//!
86//! `slurm` reads the job's SLURM environment variables and needs no system
87//! library.
88//!
89//! ## Thread Safety
90//!
91//! [`Communicator`], [`Group`], [`PersistentRequest`], [`Message`], [`Status`],
92//! [`CustomDatatype`] and [`UserOp`] are `Send + Sync`; [`Mpi`], [`Request`],
93//! `Win<T>`, its epoch handles and `WinView` (feature `rma`) are not.
94//!
95//! Which thread may call MPI is set by the provided [`ThreadLevel`]; see its
96//! documentation for the per-level rules.
97//!
98//! ## Hybrid MPI+OpenMP
99//!
100//! For hybrid parallelism, use [`Mpi::init_thread()`] with the appropriate level:
101//!
102//! - **[`Funneled`](ThreadLevel::Funneled)** (recommended): Only the main thread makes MPI calls.
103//!   OpenMP threads handle computation between MPI calls.
104//! - **[`Serialized`](ThreadLevel::Serialized)**: Any thread can make MPI calls, but only one at a time.
105//! - **[`Multiple`](ThreadLevel::Multiple)**: Full concurrent MPI from any thread (highest overhead).
106//!
107//! ```no_run
108//! use ferrompi::{Mpi, ThreadLevel, ReduceOp};
109//!
110//! // Request funneled support for hybrid MPI + threads
111//! let mpi = Mpi::init_thread(ThreadLevel::Funneled).unwrap();
112//! assert!(mpi.thread_level() >= ThreadLevel::Funneled);
113//!
114//! let world = mpi.world();
115//! // Worker threads compute locally, main thread calls MPI
116//! let local = 42.0_f64;
117//! let global = world.allreduce_scalar(local, ReduceOp::Sum).unwrap();
118//! ```
119//!
120//! ### SLURM Configuration
121//!
122//! ```bash
123//! #SBATCH --ntasks-per-node=4        # MPI ranks per node
124//! #SBATCH --cpus-per-task=8          # OpenMP threads per rank
125//! export OMP_NUM_THREADS=$SLURM_CPUS_PER_TASK
126//! srun --cpu-bind=cores ./my_program
127//! ```
128//!
129//! Use the `slurm` module (with the `slurm` feature) to read these values at runtime.
130//! See `examples/hybrid_openmp.rs` for the full pattern.
131//!
132//! ## Lifecycle
133//!
134//! [`Mpi::init`] or [`Mpi::init_thread`] comes first: until one has returned,
135//! any other call that would reach MPI returns [`Error::InvalidState`]
136//! instead, except the queries MPI allows at any time ([`Mpi::version`],
137//! [`Mpi::library_version`], [`Mpi::is_initialized`], [`Mpi::is_finalized`]).
138//! Dropping the [`Mpi`] handle finalizes MPI. See [`Mpi`] for what happens to
139//! other handles afterwards, and [`Error`] for which failures return `Err`
140//! and which abort the process.
141//!
142//! ## Extended documentation
143//!
144//! The [`doc`] module embeds the long-form guides and the architecture
145//! decision records.

215/// Process-wide buffer attached for buffered sends (`MPI_Buffer_attach`).
216///
217/// MPI allows at most one attached buffer per process. This static holds the
218/// `Box<[u8]>` so that the allocation remains valid for the duration of the
219/// attachment. The `Mutex` is held only briefly during `buffer_attach` and
220/// `buffer_detach` transitions; MPI itself manages the buffer between those
221/// two calls.
222static ATTACHED_BUFFER: Mutex<Option<Box<[u8]>>> = Mutex::new(None);

224/// MPI thread support levels.
225///
226/// | Level | Who may call MPI | Synchronization |
227/// |-------|-------------------|------------------|
228/// | [`Single`](ThreadLevel::Single) | Only the thread that called [`Mpi::init_thread`] | N/A |
229/// | [`Funneled`](ThreadLevel::Funneled) | Only the thread that called [`Mpi::init_thread`] | N/A |
230/// | [`Serialized`](ThreadLevel::Serialized) | Any thread | Caller serializes; debug builds detect an overlap |
231/// | [`Multiple`](ThreadLevel::Multiple) | Any thread | Collective calls on one communicator must be issued in the same order on every process |
232///
233/// A call from any other thread at [`Single`](ThreadLevel::Single) or
234/// [`Funneled`](ThreadLevel::Funneled) returns
235/// `Err(`[`Error::ThreadLevelViolation`]`)` without calling MPI. At
236/// [`Serialized`](ThreadLevel::Serialized), the caller must serialize its own
237/// calls; a debug build that detects two calls overlapping also returns that
238/// error (a consuming [`Request::wait`](crate::Request::wait), the final wait
239/// of a [`scope`](crate::scope()) and the closing call of an RMA epoch abort
240/// the process instead), but a release build does not check.
241///
242/// [`Mpi::thread_level()`] reports the level MPI actually granted, which may
243/// be lower than the level requested to [`Mpi::init_thread`]; it is the
244/// granted level, not the requested one, that these rules apply to.
245///
246/// At [`Serialized`](ThreadLevel::Serialized) and
247/// [`Multiple`](ThreadLevel::Multiple), MPI matches collective calls on a
248/// communicator in the order each process issues them (MPI-4.1 §11.6.2), so
249/// threads that share a communicator must issue its collective calls in the
250/// same order on every process. A mutex alone does not ensure that: the threads
251/// can take turns in a different order on each process. Give each thread its
252/// own communicator ([`Communicator::duplicate`](crate::Communicator::duplicate)),
253/// or make every collective call on one communicator from one thread.
254/// `Communicator` is `Sync`, so the compiler does not prevent the mismatch.
255#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
256#[repr(i32)]
257pub enum ThreadLevel {
258    /// Only single-threaded execution
259    Single = 0,
260    /// Multi-threaded, but MPI calls only from main thread
261    Funneled = 1,
262    /// Multi-threaded, but MPI calls serialized by user
263    Serialized = 2,
264    /// Full multi-threaded support
265    Multiple = 3,
266}

268/// MPI environment handle.
269///
270/// # Lifecycle
271///
272/// There is one `Mpi` per process. While a handle is alive,
273/// [`Mpi::init`]/[`Mpi::init_thread`] return
274/// `Err(`[`Error::AlreadyInitialized`]`)`; once it is dropped, they return
275/// `Err(`[`Error::Finalized`]`)`. MPI cannot be re-initialized.
276///
277/// Until one of the two has returned, the constructors that take no handle
278/// ([`UserOp::new`], [`UserOp::new_noncommutative`],
279/// [`CustomDatatype::contiguous`], [`CustomDatatype::vector`] and
280/// [`CustomDatatype::create_struct`]) return
281/// `Err(`[`Error::InvalidState`]`)` without calling MPI, on every thread.
282///
283/// Dropping this handle finalizes MPI. Afterward, every method that calls
284/// MPI through a communicator, group, request, window, datatype or
285/// user op returns `Err(`[`Error::Finalized`]`)` without calling MPI. The
286/// queries the MPI standard allows at any time ([`Mpi::version`],
287/// [`Mpi::library_version`], [`Mpi::is_initialized`],
288/// [`Mpi::is_finalized`]) still answer. A communicator, request, window,
289/// datatype, group or user op that outlives this handle makes no
290/// MPI call when it is dropped.
291///
292/// If any window (feature `rma`) is still alive when this handle is
293/// dropped — whatever constructed it — `MPI_Finalize` is skipped instead,
294/// with a stderr warning, because some MPI implementations free
295/// MPI-allocated window memory inside `MPI_Finalize` itself, and some abort
296/// while tearing down internal state that still tracks a live window;
297/// window memory stays valid until the process exits. Launchers can report
298/// such an exit differently from a clean one; see
299/// [`doc::mpi_compatibility`].
300///
301/// `MPI_Finalize` is also skipped, with a stderr warning, if any
302/// [`PersistentRequest`] is active, whatever thread holds it: finalizing with a
303/// request pending is erroneous (MPI-4.1 §11.2.2), and the request can be moved
304/// to a thread this drop cannot wait for. The request can still be completed
305/// with `wait`/`test` afterwards; dropping it then makes no MPI call and leaks
306/// its handle and, if it is still active, its buffers.
307///
308/// The same holds while a [`Message`] from a matched probe is unreceived,
309/// whatever thread holds it: MPI requires every matched message to be received
310/// before `MPI_Finalize` (MPI-4.1 §11.2.2). It can still be received with
311/// `mrecv`, or dropped, afterwards.
312///
313/// The same holds while a nonblocking [`scope`](crate::scope()) is open on the
314/// thread that drops this handle: its requests complete when the scope ends.
315/// A scope open on another thread is waited for instead, with no timeout, at
316/// every thread level.
317///
318/// A `wait` or `test` of a persistent request, an `mrecv`, a [`Message`] drop
319/// or a probe that matches nothing, run on another thread while this handle is
320/// dropped, can make the drop skip `MPI_Finalize`, although nothing is left
321/// outstanding once that call returns.
322///
323/// When `MPI_Finalize` is skipped, MPI stays initialized: a `wait` or `test`
324/// on a request still pending completes it, a `cancel` on one still reaches
325/// MPI, a matched [`Message`] can still be received, an open RMA epoch still
326/// issues its closing call (fence, `MPI_Win_complete`, unlock; it can wait
327/// for a peer that no longer calls MPI), and an exposure epoch can still be
328/// waited for or tested; every other call returns
329/// `Err(`[`Error::Finalized`]`)`, and handles dropped afterwards are leaked
330/// without an MPI call, except a [`Message`], whose drop still receives it.
331///
332/// At [`ThreadLevel::Single`]/[`ThreadLevel::Funneled`], dropping a handle
333/// whose `Drop` calls MPI — a [`PersistentRequest`], a communicator other than
334/// the world, a window, a datatype, group or user op — on a
335/// thread other than the one that called [`Mpi::init`]/[`Mpi::init_thread`]
336/// prints `ferrompi: <Type> dropped on thread <name or id>` to stderr and
337/// aborts the process. A [`Message`] is the exception: dropped there, it makes
338/// no MPI call and stays unreceived, so this handle's drop skips
339/// `MPI_Finalize`.
340///
341/// At [`ThreadLevel::Serialized`]/[`ThreadLevel::Multiple`], dropping this
342/// handle waits for every MPI call that other threads have in progress
343/// through this crate to return; a call that starts after the drop began
344/// returns `Err(`[`Error::Finalized`]`)` without calling MPI, except a
345/// completion, test or cancel call on a request that a scope open on another
346/// thread still holds, which the drop waits for. A `wait` or `test` on an
347/// active [`PersistentRequest`] is admitted too, and the drop does not wait for
348/// the request. So is the `mrecv` or the drop of a matched [`Message`]. The
349/// closing call of a fence, PSCW access or passive-target epoch (the unlock),
350/// `Win::wait_exposure` and `Win::test_exposure` (feature `rma`) are admitted
351/// too: the drop does not wait for an epoch, because the epoch's window keeps
352/// it on the skip path. A thread blocked forever inside an MPI call, for
353/// example in a collective its peers never enter, blocks the drop; MPI requires
354/// every thread's MPI calls to complete before `MPI_Finalize`.
355///
356/// A call that would fail one of the checks above (finalized, wrong
357/// thread) and is also given invalid arguments may return the argument
358/// error (for example [`Error::BufferSize`]) instead of
359/// `Err(`[`Error::Finalized`]`)`/`Err(`[`Error::ThreadLevelViolation`]`)`;
360/// the order in which these checks run is not part of the API.
361///
362/// # Example
363///
364/// ```no_run
365/// use ferrompi::Mpi;
366///
367/// let mpi = Mpi::init().expect("Failed to initialize MPI");
368/// let world = mpi.world();
369/// println!("Running on {} processes", world.size());
370/// // MPI is finalized when `mpi` goes out of scope
371/// ```
372pub struct Mpi {
373    /// The thread level that was provided
374    thread_level: ThreadLevel,
375    /// This process's rank in `MPI_COMM_WORLD`, read once at init
376    world_rank: i32,
377    /// The size of `MPI_COMM_WORLD`, read once at init
378    world_size: i32,
379    /// Marker to make Mpi !Send and !Sync
380    _marker: PhantomData<*const ()>,
381}
382
383impl Mpi {
384    /// Initialize MPI with single-threaded support.
385    ///
386    /// # Errors
387    ///
388    /// Returns `Err(`[`Error::AlreadyInitialized`]`)` while an `Mpi` handle
389    /// exists or another thread is initializing, `Err(`[`Error::Finalized`]`)`
390    /// once MPI has been finalized, or `Err(`[`Error::Mpi`]`)` if
391    /// `MPI_Init_thread` itself fails. An error inside `MPI_Init_thread`
392    /// itself usually aborts the process before `Err(`[`Error::Mpi`]`)` can
393    /// be returned; see [`Error`]. If MPI then fails to report this process's
394    /// rank or the size of `MPI_COMM_WORLD`, that error is returned and MPI is
395    /// finalized, as it is when an `Mpi` handle is dropped.
396    pub fn init() -> Result<Self> {
397        Self::init_thread(ThreadLevel::Single)
398    }
399
400    /// Initialize MPI with the specified thread support level.
401    ///
402    /// # Arguments
403    ///
404    /// * `required` - The minimum thread support level required
405    ///
406    /// # Returns
407    ///
408    /// Returns the MPI handle. The actual thread support level provided can be
409    /// queried with [`thread_level()`](Self::thread_level).
410    ///
411    /// # Errors
412    ///
413    /// Returns `Err(`[`Error::AlreadyInitialized`]`)` while an `Mpi` handle
414    /// exists or another thread is initializing, `Err(`[`Error::Finalized`]`)`
415    /// once MPI has been finalized, or `Err(`[`Error::Mpi`]`)` if
416    /// `MPI_Init_thread` itself fails. An error inside `MPI_Init_thread`
417    /// itself usually aborts the process before `Err(`[`Error::Mpi`]`)` can
418    /// be returned; see [`Error`]. That error's class is
419    /// [`MpiErrorClass::Unknown`], because MPI cannot be asked for the class
420    /// of an error from its own initialization. If MPI then fails to report
421    /// this process's rank or the size of `MPI_COMM_WORLD`, that error is
422    /// returned and MPI is finalized, as it is when an `Mpi` handle is dropped.
423    pub fn init_thread(required: ThreadLevel) -> Result<Self> {
424        rt::begin_init()?;
425
426        let mut already_finalized: i32 = 0;
427        // SAFETY: already_finalized is a local out-parameter that
428        // ferrompi_finalized writes before this reads it below;
429        // ferrompi_finalized is legal to call at any point in the process
430        // lifecycle, including before MPI_Init_thread.
431        unsafe { ffi::ferrompi_finalized(&mut already_finalized) };
432        if already_finalized != 0 {
433            rt::abandon_init();
434            return Err(Error::Finalized);
435        }
436
437        let mut provided: i32 = 0;
438        // SAFETY: provided is a local out-parameter written by MPI_Init_thread;
439        // rt::begin_init's compare-exchange above guarantees this is the only
440        // MPI_Init_thread call in the process at a time, and the finalized
441        // check above guarantees MPI has not already been finalized.
442        let ret = unsafe { ffi::ferrompi_init_thread(required as i32, &mut provided) };
443
444        if ret != 0 {
445            rt::abandon_init();
446            return Err(Error::Mpi {
447                class: MpiErrorClass::Unknown,
448                code: ret,
449                message: format!("MPI_Init_thread failed with code {ret}"),
450                operation: Some("init_thread"),
451            });
452        }
453
454        let thread_level = match provided {
455            0 => ThreadLevel::Single,
456            1 => ThreadLevel::Funneled,
457            2 => ThreadLevel::Serialized,
458            _ => ThreadLevel::Multiple,
459        };
460
461        // Read before `rt::activate`: until then the guard admits this thread
462        // and no other, so only MPI itself can fail these two.
463        let world = Communicator::from_handle(comm::WORLD_HANDLE);
464
465        rt::activate(thread_level);
466
467        let mut mpi = Mpi {
468            thread_level,
469            world_rank: 0,
470            world_size: 0,
471            _marker: PhantomData,
472        };
473        // If the read failed, `?` drops `mpi`, which finalizes MPI.
474        let world = world?;
475        mpi.world_rank = world.rank;
476        mpi.world_size = world.size;
477        Ok(mpi)
478    }

480    /// Get the thread support level that was provided.
481    pub fn thread_level(&self) -> ThreadLevel {
482        self.thread_level
483    }

485    /// Get a handle to `MPI_COMM_WORLD`.
486    ///
487    /// Makes no MPI call: the rank and size were read when MPI was
488    /// initialized, and neither changes afterwards.
489    pub fn world(&self) -> Communicator {
490        Communicator {
491            handle: comm::WORLD_HANDLE,
492            rank: self.world_rank,
493            size: self.world_size,
494        }
495    }

497    /// Get the current wall-clock time (`MPI_Wtime`), in seconds.
498    ///
499    /// This is a high-resolution timer suitable for benchmarking. It takes
500    /// `&self` because MPI must be initialized and not yet finalized; code
501    /// without the handle can use [`std::time::Instant`].
502    pub fn wtime(&self) -> f64 {
503        // SAFETY: ferrompi_wtime takes no pointer arguments and touches no
504        // Rust-owned memory; `&self` proves MPI is initialized and not
505        // finalized, and `Mpi` is neither `Send` nor `Sync`, so this runs on
506        // the thread that initialized MPI.
507        unsafe { ffi::ferrompi_wtime() }
508    }

510    /// Get the MPI library version string (implementation-specific).
511    ///
512    /// Returns a string such as `"Open MPI v4.1.6"` or `"Intel(R) MPI Library 2021.7"`.
513    /// This wraps `MPI_Get_library_version`.
514    /// The string ends before the first NUL character, with trailing whitespace removed.
515    pub fn library_version() -> Result<String> {
516        let mut buf = [0u8; 8192];
517        let mut len: i32 = 0;
518        // SAFETY: buf is a local 8192-byte buffer; MPI writes at most
519        // MPI_MAX_LIBRARY_VERSION_STRING bytes, which the C layer asserts at build time
520        // is at most 8192, and reports the length through the local `len`.
521        let ret = unsafe {
522            ffi::ferrompi_get_library_version(buf.as_mut_ptr().cast::<c_char>(), &mut len)
523        };
524        Error::check_with_op(ret, "get_library_version")?;
525        let len = (len.max(0) as usize).min(buf.len());
526        // Open MPI counts the terminating NUL in `len`; some implementations
527        // append trailing whitespace.
528        let len = buf[..len].iter().position(|&b| b == 0).unwrap_or(len);
529        let s = std::str::from_utf8(&buf[..len])
530            .map_err(|_| Error::Internal("Invalid UTF-8 in library version string".into()))?;
531        Ok(s.trim_end().to_string())
532    }

534    /// Get the MPI standard version string (e.g., "MPI 4.0").
535    pub fn version() -> Result<String> {
536        let mut buf = [0u8; 256];
537        let mut len: i32 = 0;
538        // SAFETY: buf is a local 256-byte buffer, large enough for an MPI
539        // version string ("MPI x.y"); the C layer writes at most buf.len()
540        // bytes into it and reports the written length through `len`.
541        let ret = unsafe { ffi::ferrompi_get_version(buf.as_mut_ptr().cast::<c_char>(), &mut len) };
542        Error::check_with_op(ret, "get_version")?;
543
544        let len = (len.max(0) as usize).min(buf.len());
545        let s = std::str::from_utf8(&buf[..len])
546            .map_err(|_| Error::Internal("Invalid UTF-8 in version string".into()))?;
547        Ok(s.to_string())
548    }

575    /// Create a communicator from a group without requiring a parent
576    /// communicator (MPI 4.0, or Open MPI 5).
577    ///
578    /// Every member of `group` must make the call, with a group of the same
579    /// members in the same order and with the same `stringtag`
580    /// (MPI-4.1 §7.4.2, p.339). These rules are not checked, here or by MPICH
581    /// and Open MPI: if the members pass different groups or string tags, the
582    /// call can block, or return communicators on which a later call blocks.
583    ///
584    /// MPI bounds the length of `stringtag`: with its terminating NUL it must
585    /// fit in `MPI_MAX_STRINGTAG_LEN` bytes, a limit of at least 63
586    /// (MPI-4.1 §7.4.2, p.339), so up to 62 bytes are portable. A tag that
587    /// does not fit in the linked library's limit is refused before any MPI
588    /// call: the limit is 256 in MPICH 4.2 and, unless the library was built
589    /// with another, 1024 in Open MPI 5.0.
590    ///
591    /// Returns `Ok(Some(comm))` to a member of `group`, and `Ok(None)` when
592    /// MPI creates no communicator for the caller:
593    /// - with the empty group, where the call is local
594    ///   (MPI-4.1 §7.4.2, p.339);
595    /// - on a rank that is not a member of a non-empty `group`. MPI-4.1 does
596    ///   not spell this case out for `MPI_Comm_create_from_group`: it calls the
597    ///   function similar to `MPI_Comm_create_group`, which returns no
598    ///   communicator to such a rank (MPI-4.1 §7.4.2, p.328). MPICH 4.2 and
599    ///   Open MPI 5.0 return none here.
600    ///
601    /// # Errors
602    ///
603    /// - Returns `Err(`[`Error::InvalidArgument`]`)` if `stringtag` contains a
604    ///   NUL byte, or does not fit in the library's `MPI_MAX_STRINGTAG_LEN`
605    ///   bytes with its terminating NUL (no MPI call is made in either case).
606    /// - Returns `Err(Error::NotSupported(_))` when ferrompi was built
607    ///   against an MPI older than 4.0 other than Open MPI 5, whatever the
608    ///   length of the tag: such a library defines no limit.
609    /// - Returns `Err(Error::Mpi { .. })` if the underlying MPI call fails.
610    /// - Returns `Err(`[`Error::ResourceExhausted`]`)` if the communicator
611    ///   table is full.
612    ///
613    /// # Example
614    ///
615    /// ```no_run
616    /// use ferrompi::Mpi;
617    ///
618    /// let mpi = Mpi::init().unwrap();
619    /// let world = mpi.world();
620    /// let g = world.group().unwrap();
621    /// // All ranks participate with the same tag.
622    /// let comm = mpi
623    ///     .create_from_group(&g, "my-tag")
624    ///     .unwrap()
625    ///     .expect("every rank is in the group");
626    /// assert_eq!(comm.size(), world.size());
627    /// ```
628    pub fn create_from_group(
629        &self,
630        group: &group::Group,
631        stringtag: &str,
632    ) -> Result<Option<Communicator>> {
633        let c_tag = CString::new(stringtag).map_err(|_| Error::InvalidArgument {
634            arg: "stringtag",
635            reason: "contains a NUL byte",
636        })?;
637        // SAFETY: the call takes no argument and makes no MPI call.
638        let limit = unsafe { ffi::ferrompi_max_stringtag_len() };
639        // The limit counts the terminating NUL (MPI-4.1 §19.3.9, p.847). An
640        // allocation is at most `isize::MAX` bytes, so the cast is exact.
641        if c_tag.as_bytes_with_nul().len() as i64 > limit {
642            return Err(Error::InvalidArgument {
643                arg: "stringtag",
644                reason: "longer than MPI_MAX_STRINGTAG_LEN allows",
645            });
646        }
647        let mut new_handle: i32 = -1;
648        // SAFETY: c_tag.as_ptr() is a valid, null-terminated C string that
649        // lives for the duration of this call. group.handle is a valid group
650        // handle obtained from ferrompi_comm_group or a group-constructor shim.
651        // &mut new_handle is a pointer to a stack-allocated i32.
652        let ret = unsafe {
653            ffi::ferrompi_comm_create_from_group(group.handle, c_tag.as_ptr(), &mut new_handle)
654        };
655        Error::check_with_op(ret, "comm_create_from_group")?;
656        Communicator::from_optional_handle(new_handle)
657    }

659    /// Attach a user-provided buffer for use by buffered sends.
660    ///
661    /// This wraps `MPI_Buffer_attach`. Once attached, the buffer is owned by
662    /// MPI until [`buffer_detach`](Self::buffer_detach) is called. Only one
663    /// buffer may be attached per process at a time; attempting to attach a
664    /// second buffer without first detaching returns
665    /// `Err(`[`Error::InvalidState`]`)`.
666    ///
667    /// The `buffer` is stored in a process-wide static so its allocation
668    /// remains valid for the lifetime of the attachment. You must not access
669    /// the raw bytes of `buffer` between `buffer_attach` and `buffer_detach` —
670    /// MPI owns the contents during that window.
671    ///
672    /// # Buffer Sizing
673    ///
674    /// The recommended buffer size for `N` buffered sends of `count` elements
675    /// of type `T` is:
676    ///
677    /// ```text
678    /// N * (MPI_BSEND_OVERHEAD + count * size_of::<T>())
679    /// ```
680    ///
681    /// `MPI_BSEND_OVERHEAD` is implementation-specific; use at least a few
682    /// hundred extra bytes per buffered send. For safety, use a generous margin.
683    ///
684    /// Buffers larger than `i32::MAX` bytes are rejected with
685    /// `Err(`[`Error::InvalidArgument`]`)` before the FFI call; the
686    /// underlying `MPI_Buffer_attach` takes an `int` count and cannot
687    /// address larger buffers. An empty buffer is rejected the same way:
688    /// every MPI refuses it, each with an error of its own.
689    ///
690    /// # Errors
691    ///
692    /// - [`Error::InvalidArgument`] if `buffer` is empty or
693    ///   `buffer.len() > i32::MAX as usize`.
694    /// - [`Error::InvalidState`] if a buffer is already attached.
695    /// - [`Error::Mpi`] if `MPI_Buffer_attach` fails.
696    ///
697    /// # Example
698    ///
699    /// ```no_run
700    /// # use ferrompi::Mpi;
701    /// let mpi = Mpi::init().unwrap();
702    /// mpi.buffer_attach(vec![0u8; 64 * 1024].into_boxed_slice()).unwrap();
703    /// // ... buffered sends here ...
704    /// let _ = mpi.buffer_detach().unwrap();
705    /// ```
706    pub fn buffer_attach(&self, buffer: Box<[u8]>) -> Result<()> {
707        let mut guard = ATTACHED_BUFFER
708            .lock()
709            .map_err(|_| Error::Internal("ATTACHED_BUFFER mutex poisoned".into()))?;
710        if guard.is_some() {
711            return Err(Error::InvalidState {
712                reason: "a buffer is already attached",
713            });
714        }
715        if buffer.is_empty() {
716            return Err(Error::InvalidArgument {
717                arg: "buffer",
718                reason: "empty",
719            });
720        }
721        if buffer.len() > i32::MAX as usize {
722            return Err(Error::InvalidArgument {
723                arg: "buffer",
724                reason: "longer than i32::MAX bytes",
725            });
726        }
727        let ptr = buffer.as_ptr() as *mut std::ffi::c_void;
728        let size = buffer.len() as i64;
729        // Store the box in the static BEFORE calling MPI so the memory is
730        // guaranteed alive when MPI begins using the buffer.
731        *guard = Some(buffer);
732        // SAFETY: ptr points to the boxed slice we just stored in the static;
733        // the allocation remains valid until buffer_detach drops it. size is
734        // the exact byte length of that allocation.
735        let ret = unsafe { ffi::ferrompi_buffer_attach(ptr, size) };
736        if ret != 0 {
737            // Roll back: reclaim the box so the caller can retry.
738            guard.take();
739            return Err(Error::from_code_with_op(ret, "buffer_attach"));
740        }
741        Ok(())
742    }
743
744    /// Detach the previously attached buffer and return it to the caller.
745    ///
746    /// This wraps `MPI_Buffer_detach`. The call **blocks** until all buffered
747    /// sends that are currently using the buffer have completed. Once this
748    /// returns, the returned `Box<[u8]>` is owned by the caller again and
749    /// may be dropped or reused.
750    ///
751    /// Do **not** call this from a `Drop` implementation (e.g., on a wrapper
752    /// around `Mpi`). `MPI_Buffer_detach` blocks until pending sends drain;
753    /// blocking inside `Drop` can produce hard-to-diagnose hangs.
754    ///
755    /// # Errors
756    ///
757    /// - [`Error::InvalidState`] if no buffer is currently attached.
758    /// - [`Error::Mpi`] if `MPI_Buffer_detach` fails.
759    ///
760    /// # Example
761    ///
762    /// ```no_run
763    /// # use ferrompi::Mpi;
764    /// let mpi = Mpi::init().unwrap();
765    /// mpi.buffer_attach(vec![0u8; 64 * 1024].into_boxed_slice()).unwrap();
766    /// // ... buffered sends ...
767    /// let _buf = mpi.buffer_detach().unwrap(); // dropped here
768    /// ```
769    pub fn buffer_detach(&self) -> Result<Box<[u8]>> {
770        let mut guard = ATTACHED_BUFFER
771            .lock()
772            .map_err(|_| Error::Internal("ATTACHED_BUFFER mutex poisoned".into()))?;
773        if guard.is_none() {
774            return Err(Error::InvalidState {
775                reason: "no buffer is attached",
776            });
777        }
778        let mut out_ptr: *mut std::ffi::c_void = std::ptr::null_mut();
779        let mut out_size: i64 = 0;
780        // SAFETY: out_ptr and out_size are valid stack-allocated output parameters.
781        // MPI_Buffer_detach writes the buffer pointer and its size into them.
782        let ret = unsafe { ffi::ferrompi_buffer_detach(&mut out_ptr, &mut out_size) };
783        if ret != 0 {
784            return Err(Error::from_code_with_op(ret, "buffer_detach"));
785        }
786        // Reclaim the Box from the static; this is the same allocation MPI just
787        // released. We take() here so the static is cleared atomically.
788        Ok(guard.take().expect("guard was Some; take() must succeed"))
789    }
790}

792impl Drop for Mpi {
793    fn drop(&mut self) {
794        // rt::begin_finalize() moves the lifecycle state from Active to
795        // Finalizing, which refuses new calls, frees and scope opens but
796        // still admits the completion calls of requests already pending, and
797        // at Serialized/Multiple waits for the calls other threads have in
798        // progress. If finalize_skip_reason() names a reason, the state stays
799        // Finalizing for the rest of the process and MPI stays initialized.
800        // Otherwise rt::end_finalize() stores Finalized, waits for the
801        // completion calls admitted meanwhile, and only then does
802        // ferrompi_finalize run, so a handle whose drop is nested inside the
803        // finalize sweep (a closure captured by a request/op that the sweep
804        // drops) observes Finalized and makes no MPI call. begin_finalize
805        // returns false for a stub Mpi built without init (Uninit) and for a
806        // second call on an already-finalized state, so this runs
807        // ferrompi_finalize at most once.
808        if !rt::begin_finalize() {
809            return;
810        }
811        if let Some(reason) = finalize_skip_reason() {
812            // A single write so concurrent ranks' output cannot interleave mid-line.
813            let msg = format!("ferrompi: MPI_Finalize skipped: {reason}\n");
814            let _ = std::io::stderr().write_all(msg.as_bytes());
815            return;
816        }
817        rt::end_finalize();
818        // SAFETY: rt::begin_finalize() just returned true, so state was Active —
819        // MPI_Init(_thread) succeeded and MPI_Finalize has not yet been
820        // called for this process.
821        unsafe {
822            ffi::ferrompi_finalize();
823        }
824    }
825}
826
827/// Why `Mpi::drop` must not call `MPI_Finalize`, or `None` when it may: a
828/// nonblocking scope open on the dropping thread, an active persistent request
829/// or an unreceived matched message on any thread, or a live window (feature
830/// `rma`). This is the one place the skip is decided.
831fn finalize_skip_reason() -> Option<String> {
832    if rt::scopes_on_this_thread() > 0 {
833        return Some(
834            "a nonblocking scope is still open on this thread; its requests complete when the scope ends"
835                .into(),
836        );
837    }
838    let live = rt::live_handle_tokens();
839    if live > 0 {
840        return Some(format!(
841            "{live} persistent request(s) still active or matched message(s) not yet received; request buffers stay valid until the process exits"
842        ));
843    }
844    #[cfg(feature = "rma")]
845    {
846        let live = window::live_windows();
847        if live > 0 {
848            return Some(format!(
849                "{live} window(s) still alive; their memory stays valid until the process exits"
850            ));
851        }
852    }
853    None
854}

1213    /// The longest `stringtag` the linked library allows passes the length
1214    /// check, and one byte more is refused by it. MPI is never initialized
1215    /// here: a tag that passes goes on to the lifecycle guard, which refuses
1216    /// the call, so no MPI call is made either way.
1217    #[test]
1218    fn create_from_group_checks_the_length_of_the_tag() {
1219        let mpi = stub_mpi();
1220        let g = group::Group { handle: 0 };
1221        // SAFETY: the call takes no argument and makes no MPI call.
1222        let limit = unsafe { crate::ffi::ferrompi_max_stringtag_len() };
1223        // Without `MPI_Comm_create_from_group` the library defines no limit,
1224        // and no length is refused.
1225        let longest = if limit == i64::MAX {
1226            4096
1227        } else {
1228            assert!(limit >= 63, "MPI-4.1 requires at least 63, got {limit}");
1229            usize::try_from(limit).expect("the limit is positive") - 1
1230        };
1231
1232        let result = mpi.create_from_group(&g, &"t".repeat(longest));
1233        assert!(
1234            matches!(
1235                result,
1236                Err(Error::InvalidState {
1237                    reason: "MPI is not initialized"
1238                })
1239            ),
1240            "a tag of {longest} bytes passes the length check"
1241        );
1242        if limit != i64::MAX {
1243            let result = mpi.create_from_group(&g, &"t".repeat(longest + 1));
1244            assert!(
1245                matches!(
1246                    result,
1247                    Err(Error::InvalidArgument {
1248                        arg: "stringtag",
1249                        reason: "longer than MPI_MAX_STRINGTAG_LEN allows"
1250                    })
1251                ),
1252                "a tag of {} bytes is refused",
