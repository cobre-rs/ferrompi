Part II · Chapter 15

Patterns from real programs

The programs ferrompi is written for are iterative solvers: they repeat the same communication every iteration, often thousands of times, on data that differs from rank to rank. This chapter reads the communication of one, ferrompi’s SDDP example, and takes out the patterns it is built from, each with a program of its own.

By the end of the chapter you can state the rule that every pattern here keeps, divide a set of items among the ranks without exchanging counts, exchange results whose length only their rank knows, stop a loop on every rank at the same iteration, get the same bits from a floating-point sum on every rank, and have every rank stop together when one of them fails.

The excerpts below come from examples/sddp_pattern.rs and name it. CI checks that every excerpt still matches the file, and the example itself runs as an MPI test.

The rule

Every rank runs the same program on different data. A real program keeps one rule while it does: the data never changes which collective calls a rank makes. Every rank of a communicator makes the same collective calls, in the same order, with arguments that agree: the same root, the same operation, counts that match. When one rank breaks it, the others wait in a collective that rank never calls, and the job hangs (chapter 3).

A short program keeps the rule by having no branches. A solver has them everywhere the data reaches its control flow: a loop that runs until the answer is good enough, an input that can be malformed on one rank, results whose size depends on the data, and floating-point sums whose last bits feed a test. Each pattern below keeps the rule in one of those places.

The shape of a solver

SDDP, stochastic dual dynamic programming, solves optimization problems that unfold over stages under uncertainty, such as scheduling reservoirs and power plants over a year of uncertain inflows. Each iteration has a forward pass, which simulates scenarios and yields trial points and costs, and a backward pass, which builds cuts, linear bounds on the future cost, at those points. The ranks share the scenarios’ work, so each iteration exchanges the trial points and the cuts, and ends with the bounds and a convergence test.

examples/sddp_pattern.rs is the communication of such a solver without the solving. Its start-up:

fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Start-up: only the main thread calls MPI, which is `Funneled`.
    let mpi = Mpi::init_thread(ThreadLevel::Funneled)?;
    if mpi.thread_level() < ThreadLevel::Funneled {
        println!(
            "sddp_pattern: MPI provided {:?}, Funneled is needed",
            mpi.thread_level()
        );
        return Ok(());
    }
    let world = mpi.world();
    // The processes of one node share memory.
    let node = world.split_shared()?;
    let win = Win::<f64>::allocate_shared(&node, COUNT)?;
    let mut ctx: Box<Ctx> = Box::new(Ctx {
        win,
        node,
        world,
        mpi,
    });
    let rank = ctx.world.rank();
    let size = ctx.world.size();
    // …
    // `ctx` drops here: the window, then the communicators, then `MPI_Finalize`.
    Ok(())
}

In the solver it stands for, threads solve the linear programs and only the main thread calls MPI, so the program asks for Funneled and checks what it got (chapter 6). The processes of a node share one window for the scenario data (chapter 5). One boxed context owns Mpi and every handle for the whole run, with mpi as its last field, so that the window and the communicators are freed before MPI is finalized (chapter 11); the last lines of main say so.

Dividing the work

A solver divides its scenarios, cells or rows among the ranks. When every rank knows the number of items and the number of ranks, it can compute every rank’s share without asking, so nothing needs to be exchanged to know who has what:

use ferrompi::Mpi;

const N: usize = 10;

/// The items of `n` that rank `r` of `p` owns, as (first, count): every rank
/// gets `n / p`, and the first `n % p` ranks one more.
fn block(n: usize, p: usize, r: usize) -> (usize, usize) {
    let (base, extra) = (n / p, n % p);
    (r * base + r.min(extra), base + usize::from(r < extra))
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mpi = Mpi::init()?;
    let world = mpi.world();
    let (rank, size) = (
        usize::try_from(world.rank())?,
        usize::try_from(world.size())?,
    );

    let (first, count) = block(N, size, rank);
    println!("rank {rank}: items {first}..{}", first + count);
    // The work on each item this rank owns.
    let mine: Vec<f64> = (first..first + count).map(|i| (i * i) as f64).collect();

    // Every rank can compute every block, so the counts need no exchange.
    let mut counts = Vec::with_capacity(size);
    let mut displs = Vec::with_capacity(size);
    for r in 0..size {
        let (first, count) = block(N, size, r);
        counts.push(i32::try_from(count)?);
        displs.push(i32::try_from(first)?);
    }
    let mut all = if rank == 0 { vec![0.0; N] } else { Vec::new() };
    world.gatherv(&mine, &mut all, &counts, &displs, 0)?;
    if rank == 0 {
        println!("rank 0: {all:?}");
    }
    Ok(())
}
rank 0: items 0..4
rank 1: items 4..7
rank 2: items 7..10
rank 0: [0.0, 1.0, 4.0, 9.0, 16.0, 25.0, 36.0, 49.0, 64.0, 81.0]

block gives each rank n / p items, and one more to each of the first n % p ranks, so the shares differ by one item at most and cover every item once. Since every rank computes every share, the counts and displacements of gatherv come from the same function; chapter 3’s gatherv needed a collective first only because the counts were known to their own rank alone.

The conversions to i32 are checked with ?: a v-collective takes its counts and displacements as i32, and the C layer refuses one whose buffer holds more than INT_MAX elements (chapter 10).

Results of unknown length

A cut’s size depends on the problem, and the number of cuts a rank makes depends on its scenarios, so only the rank that made them knows how many bytes they take. The SDDP example sends them as bytes, lengths first:

    // The forward pass shares its trial points and the backward pass its cuts
    // as serialized bytes of a different length on each rank. The byte counts
    // go first, then the bytes, packed in rank order.
    let mine = cut_bytes(rank);
    let mut counts = vec![0i32; size as usize];
    ctx.world
        .allgather(&[i32::try_from(mine.len())?], &mut counts)?;
    let mut displs = Vec::with_capacity(counts.len());
    let mut total = 0i32;
    for &count in &counts {
        displs.push(total);
        total = total
            .checked_add(count)
            .ok_or("the exchanged cuts exceed i32::MAX bytes")?;
    }
    let mut recv = vec![0u8; usize::try_from(total)?];
    ctx.world.allgatherv(&mine, &mut recv, &counts, &displs)?;
    // Every rank regenerates what all ranks sent, so it can check what it got.
    let expected: Vec<u8> = (0..size).flat_map(cut_bytes).collect();
    assert_eq!(recv, expected);
    let cuts = recv
        .chunks_exact(8)
        .map(|b| b.try_into().map(f64::from_le_bytes))
        .collect::<Result<Vec<f64>, _>>()?;

It is chapter 3’s two collectives, with what a real program adds. Every rank needs every cut, so both steps are allgathers. The data is serialized to bytes, so one call moves any structure, and the receiver decodes it with chunks_exact. The lengths cross as i32, and the running total is summed with checked_add, so a total above i32::MAX bytes is an error, not a negative displacement. The example then regenerates what every rank sent and compares, which is how a test of such an exchange knows what it received.

Between two ranks, a message of unknown size needs no length first: probe it and receive it as matched (chapter 2).

Deciding together when to stop

An iterative solver stops when its error is small enough. Each rank knows only its own part of the error, and each part shrinks at its own pace. If each rank tested its own, each would leave the loop at a different iteration, and the rule would break. The test has to be on a collective result:

use ferrompi::{Mpi, ReduceOp};

const TOL: f64 = 1e-3;

fn main() -> Result<(), ferrompi::Error> {
    let mpi = Mpi::init()?;
    let world = mpi.world();
    let rank = world.rank();

    // Each rank's part of the problem converges at its own pace.
    let mut error = f64::from(rank + 1);
    let mut iteration = 0;
    let mut below = None;
    loop {
        iteration += 1;
        error *= 0.5; // one step of the local solve
        if error < TOL && below.is_none() {
            below = Some(iteration);
        }
        // Whether to go on is decided by every rank together.
        if world.allreduce_scalar(error, ReduceOp::Max)? < TOL {
            break;
        }
    }
    let below = below.expect("the largest error is below, so this one is");
    println!("rank {rank}: below the tolerance at iteration {below}, stopped at {iteration}");
    Ok(())
}
rank 0: below the tolerance at iteration 10, stopped at 12
rank 1: below the tolerance at iteration 11, stopped at 12
rank 2: below the tolerance at iteration 12, stopped at 12

Rank 0 runs two iterations more than its part needs. That is the price of the rule, and it is the right one: the global error is what the solver reports, and it is above the tolerance until every part is below it.

The operation depends on what the test asks. Max of the errors, or Min of a flag that is 1 when a rank is done, says whether every rank is done; Max of the flag says whether any is. The SDDP example’s test says which ranks are done: each sets its own bit, and the BitwiseOr is the set of them:

    // Convergence test: each rank sets bit `rank % 64`, so with up to 64
    // ranks the OR is the set of ranks that have converged.
    let flags = ctx
        .world
        .allreduce_scalar(1u64 << (rank % 64), ReduceOp::BitwiseOr)?;
    assert_eq!(
        flags,
        if size >= 64 {
            u64::MAX
        } else {
            (1u64 << size) - 1
        }
    );

The test costs one allreduce of one value per iteration, small next to the work of an iteration; a solver that runs it thousands of times can make it persistent (chapter 3).

The same bits on every rank

A floating-point sum depends on the order of its terms, and a reduction adds in an order the library chooses (chapter 3). That matters most where a sum feeds a decision: two ranks that compare a bound with a tolerance must compare the same bits, or one goes on while the other stops. The order can be fixed by gathering the terms to every rank and adding them there:

use ferrompi::{Mpi, ReduceOp};

/// Neumaier's compensated sum, in the order of `xs`.
fn neumaier(xs: &[f64]) -> f64 {
    let (mut sum, mut err) = (0.0, 0.0);
    for &x in xs {
        let t = sum + x;
        err += if sum.abs() >= x.abs() {
            (sum - t) + x
        } else {
            (x - t) + sum
        };
        sum = t;
    }
    sum + err
}

fn main() -> Result<(), ferrompi::Error> {
    let mpi = Mpi::init()?;
    let world = mpi.world();
    let rank = world.rank();

    // One value per rank: two that cancel, and 1 between them.
    let big = 2f64.powi(60);
    let mine = [big, 1.0, -big][rank as usize % 3];
    let mut all = vec![0.0; world.size() as usize];
    world.allgather(&[mine], &mut all)?;

    if rank == 0 {
        let in_order: f64 = all.iter().sum();
        let other: f64 = [all[0], all[2], all[1]].iter().sum();
        println!("ranks 0, 1, 2: {in_order}");
        println!("ranks 0, 2, 1: {other}");
        println!("compensated, ranks 0, 1, 2: {}", neumaier(&all));
    }
    // Every rank sums the same values in the same order: check that the bits agree.
    let bits = neumaier(&all).to_bits();
    let same = world.allreduce_scalar(bits, ReduceOp::Min)?
        == world.allreduce_scalar(bits, ReduceOp::Max)?;
    println!("rank {rank}: the same bits as every rank: {same}");
    Ok(())
}
ranks 0, 1, 2: 0
ranks 0, 2, 1: 1
compensated, ranks 0, 1, 2: 1
rank 0: the same bits as every rank: true
rank 1: the same bits as every rank: true
rank 2: the same bits as every rank: true

Added in rank order, the 1 is lost against 260, whose spacing between doubles is 256; added after the two large terms cancel, it is kept. Neumaier’s compensated sum carries the lost part along and gets 1 in either order here. After the allgather, every rank holds the same values in rank order, so every rank computes the same bits, and the Min and Max of those bits, as an integer, agree exactly when every rank has them.

The SDDP example does the same with its bound, and checks it against a serial sum:

    // A bound summed by `allreduce` is summed in MPI's order, so its last bits
    // may change between runs. The gathered values are in rank order on every
    // rank: summing them there with a compensated sum is bit-identical on every
    // rank and to a serial sum.
    let oracle: Vec<f64> = (0..size)
        .flat_map(|r| (0..=r as usize).map(move |k| value(r, k)))
        .collect();
    let bound = neumaier(&cuts).to_bits();
    assert_eq!(bound, neumaier(&oracle).to_bits());
    assert_eq!(
        ctx.world.allreduce_scalar(bound, ReduceOp::Min)?,
        ctx.world.allreduce_scalar(bound, ReduceOp::Max)?
    );

Gathering every term costs memory and bandwidth that a reduction does not, so a solver does it for the few sums that decide something, and reduces the rest. Sums of integers that do not overflow, and Min and Max of anything, have no order to fix.

When one rank fails

An error on one rank breaks the rule in the most common way: that rank returns from main, and the others wait in the next collective. A real program catches the error on the rank that has it, turns it into a value, and lets every rank learn it before going on:

use ferrompi::{Communicator, Mpi, ReduceOp};

/// Every rank's verdict on its own step, combined: `Ok` on every rank, or the
/// same list of the ranks that failed on every rank.
fn agree(world: &Communicator, ok: bool) -> ferrompi::Result<Result<(), Vec<i32>>> {
    let mut all = vec![0i32; world.size() as usize];
    world.allgather(&[i32::from(ok)], &mut all)?;
    let failed: Vec<i32> = (0..world.size())
        .filter(|&r| all[r as usize] == 0)
        .collect();
    Ok(if failed.is_empty() {
        Ok(())
    } else {
        Err(failed)
    })
}

fn main() -> Result<(), ferrompi::Error> {
    let mpi = Mpi::init()?;
    let world = mpi.world();
    let rank = world.rank();

    // Each rank reads its own part of the input. Rank 1's is malformed.
    let text = if rank == 1 { "2,5" } else { "2.5" };
    let value = match text.parse::<f64>() {
        Ok(v) => Some(v),
        Err(e) => {
            println!("rank {rank}: cannot read {text:?}: {e}");
            None
        }
    };

    // Before the next collective, every rank learns whether all can go on.
    match agree(&world, value.is_some())? {
        Ok(()) => {
            let value = value.expect("every rank read its part");
            let total = world.allreduce_scalar(value, ReduceOp::Sum)?;
            println!("rank {rank}: total {total}");
        }
        Err(failed) => println!("rank {rank}: ranks {failed:?} failed, stopping"),
    }
    Ok(())
}
rank 1: cannot read "2,5": invalid float literal
rank 0: ranks [1] failed, stopping
rank 1: ranks [1] failed, stopping
rank 2: ranks [1] failed, stopping

agree is a collective, so every rank calls it, failed or not, and every rank gets the same answer, so every rank takes the same branch. An allgather of the flags tells every rank which ranks failed; the Min of the flags would say only whether one did, which is what ferrompi’s MPI tests use (chapter 13). Rank 1 prints its own error, since only it has the message.

The pattern needs a point where every rank can still reach the agreement. When a rank cannot, because its state is lost or it is about to panic in the middle of a step, world.abort(code) asks MPI to end every process of the job, and never returns (chapter 1). Abort loses the other ranks’ work and their chance to report, so a solver agrees where it can and aborts where it must.

Summary

  • Every pattern keeps one rule: the data never changes which collective calls a rank makes, or in what order, or with which root and operation.
  • An SDDP solver’s iteration is a broadcast, an exchange of trial points and cuts, bounds and statistics, a convergence test and reads of shared scenario data, around a context that owns every handle with Mpi last.
  • When every rank can compute every share of the work, the counts of a v-collective need no exchange.
  • Data whose length only its rank knows is sent in two collectives, lengths and then bytes, with the total checked against i32::MAX.
  • A loop stops on a collective result, such as the Max of the errors, so every rank stops at the same iteration.
  • A sum that decides something is added in a fixed order on every rank, from gathered terms, and its bits can be checked with Min and Max.
  • An error is turned into a value and agreed on by every rank before the next collective; abort is for the rank that cannot reach the agreement.
