Struct Win

pub struct Win<T: MpiDatatype> { /* private fields */ }
Available on crate feature rma only.
Expand description

A general-purpose RMA window.

Win<T> wraps one of:

  • MPI_Win_create (Win::create) — the caller supplies a Vec<T> and the window owns it; into_buffer returns it.
  • MPI_Win_allocate (Win::allocate) — MPI allocates the buffer.
  • MPI_Win_allocate_shared (Win::allocate_shared) — MPI allocates memory that every process of a shared-memory communicator can access directly, and remote returns a view of each rank’s region.

Every constructor but Win::allocate_shared works across nodes, and the window is the foundation for all RMA operations (Put, Get, Accumulate, etc.) in this library.

§Ownership

Win::create owns its Vec for as long as MPI may use it, and into_buffer returns it. Dropping or forgetting the window never frees a buffer a peer may still access: the buffer is released only after MPI_Win_free has succeeded, and leaked in every other case.

§Dropping

MPI_Win_free is collective and is called when the Win is dropped. It ends in one of four ways:

  • The free succeeds: the window leaves the live-window count, and the buffer of a Win::create window is dropped after the call. For Win::allocate and Win::allocate_shared, the free also releases the MPI-managed buffer.
  • Mpi is being dropped, or was dropped and skipped MPI_Finalize because this window was alive: no MPI call is made, the window stays counted as alive (so Mpi skips MPI_Finalize), and the buffer is leaked. Its memory stays valid until the process exits.
  • The free fails: the buffer is leaked and the window stays counted as alive.
  • An exposure epoch opened by post is still open: no MPI call is made, the window stays counted as alive (so Mpi skips MPI_Finalize), and the buffer is leaked, because a peer may still write into the window (MPI-4.1 §12.2.5).

§Thread Safety

Win is intentionally not Send or Sync. MPI windows have specific thread-safety rules that depend on the MPI thread level.

§Compile-time guarantees

Win::fence, Win::start, Win::lock and Win::lock_all borrow the window mutably for as long as their closure runs, and give it a handle with the invariant lifetimes of Scope: 's is the epoch, and every buffer an operation names is borrowed for 's, which ends only after the closing call that completes the operation. Each program below does not compile, and is followed by the same program made correct. Each is the body of a function that takes the window by &mut, or the communicator when the program must own the window.

§Buffers

A buffer declared inside the closure would be freed before the closing call, so the first program is rejected. The rejection also shows that 's is invariant: were it covariant, the compiler could shorten 's to the buffer’s lifetime and accept the program.

ⓘ
let none = WinFenceAssert::none();
win.fence(none, none, |e| {
    let origin = [1u64; 4];
    e.put(&origin, 1, 0)
})
let none = WinFenceAssert::none();
let origin = [1u64; 4];
win.fence(none, none, |e| {
    e.put(&origin, 1, 0)
})

A buffer cannot be dropped while the epoch borrows it:

ⓘ
let none = WinFenceAssert::none();
let origin = vec![1u64; 4];
win.fence(none, none, |e| {
    e.put(&origin, 1, 0)?;
    drop(origin);
    Ok(())
})
let none = WinFenceAssert::none();
let origin = vec![1u64; 4];
win.fence(none, none, |e| {
    e.put(&origin, 1, 0)?;
    Ok(())
})?;
drop(origin);
Ok(())

Nor can it be written, because MPI may still be reading it:

ⓘ
let none = WinFenceAssert::none();
let mut origin = vec![1u64; 4];
win.fence(none, none, |e| {
    e.put(&origin, 1, 0)?;
    origin[0] = 2;
    Ok(())
})
let none = WinFenceAssert::none();
let mut origin = vec![1u64; 4];
win.fence(none, none, |e| {
    e.put(&origin, 1, 0)?;
    Ok(())
})?;
origin[0] = 2;
Ok(())

§Results MPI writes

A get destination, a get_accumulate result and a fetch_and_op or compare_and_swap result are written when the closing call returns, and stay borrowed until then. Reading one inside the epoch, which would see a value MPI has not written yet, is rejected:

ⓘ
let none = WinFenceAssert::none();
let origin = 1u64;
let mut old = 0u64;
win.fence(none, none, |e| {
    e.fetch_and_op(&origin, &mut old, 1, 0, ReduceOp::Sum)?;
    Ok(old)
})
let none = WinFenceAssert::none();
let origin = 1u64;
let mut old = 0u64;
win.fence(none, none, |e| {
    e.fetch_and_op(&origin, &mut old, 1, 0, ReduceOp::Sum)
})?;
Ok(old)

The storage of a result cannot be dropped inside the epoch either:

ⓘ
let none = WinFenceAssert::none();
let origin = 1u64;
let mut old = Box::new(0u64);
win.fence(none, none, |e| {
    e.fetch_and_op(&origin, &mut *old, 1, 0, ReduceOp::Sum)?;
    drop(old);
    Ok(())
})
let none = WinFenceAssert::none();
let origin = 1u64;
let mut old = Box::new(0u64);
win.fence(none, none, |e| {
    e.fetch_and_op(&origin, &mut *old, 1, 0, ReduceOp::Sum)?;
    Ok(())
})?;
drop(old);
Ok(())

§The handle

The handle is borrowed for 's, so it cannot leave the closure, whether it is stored outside:

ⓘ
let none = WinFenceAssert::none();
let mut keep = None;
win.fence(none, none, |e| {
    keep = Some(e);
    Ok(())
})
let none = WinFenceAssert::none();
win.fence(none, none, |e| {
    let mut keep = None;
    keep = Some(e);
    Ok(())
})

or returned, which the compiler reports without an error code:

ⓘ
let none = WinFenceAssert::none();
let _kept = win.fence(none, none, |e| Ok(e))?;
Ok(())
let none = WinFenceAssert::none();
let _kept = win.fence(none, none, |e| Ok(()))?;
Ok(())

§The window itself

The epoch borrows the window mutably, so epochs cannot nest on one window. An owned window nests the same way, with error E0499 in place of E0500:

ⓘ
let none = WinFenceAssert::none();
win.fence(none, none, |_| {
    win.fence(none, none, |_| Ok(()))
})
let none = WinFenceAssert::none();
win.fence(none, none, |_| Ok(()))?;
win.fence(none, none, |_| Ok(()))

The window’s view cannot be taken inside the epoch either: the epoch holds the window mutably, while a peer may be writing it. Take the handle’s view instead:

ⓘ
let none = WinFenceAssert::none();
win.fence(none, none, |e| {
    let _local = win.local();
    Ok(())
})
let none = WinFenceAssert::none();
win.fence(none, none, |e| {
    let _local = e.local();
    Ok(())
})

The window hands out no safe slice of its memory, so the call that used to return one no longer exists:

ⓘ
let _local = win.local_slice();
let _local = win.local();

§Views

A WinView borrows what it came from. A handle’s view cannot leave the closure, whether it is stored outside:

ⓘ
let mut keep = None;
win.lock_all(|e| {
    keep = Some(e.local());
    Ok(())
})
win.lock_all(|e| {
    let mut keep = None;
    keep = Some(e.local());
    Ok(())
})

A view of a peer’s region of a shared window is borrowed the same way, from either handle:

ⓘ
let mut keep = None;
win.lock_all(|e| {
    keep = Some(e.remote(1)?);
    Ok(())
})
win.lock_all(|e| {
    let mut keep = None;
    keep = Some(e.remote(1)?);
    Ok(())
})
ⓘ
let none = WinFenceAssert::none();
let mut keep = None;
win.fence(none, none, |e| {
    keep = Some(e.remote(1)?);
    Ok(())
})
let none = WinFenceAssert::none();
win.fence(none, none, |e| {
    let mut keep = None;
    keep = Some(e.remote(1)?);
    Ok(())
})

A window’s view cannot be held across an epoch, which borrows the window mutably while a peer may be writing it:

ⓘ
let none = WinFenceAssert::none();
let local = win.local();
win.fence(none, none, |_| Ok(()))?;
local.read(0);
Ok(())
let none = WinFenceAssert::none();
win.fence(none, none, |_| Ok(()))?;
let local = win.local();
local.read(0);
Ok(())

Nor can a window’s view of a peer’s region:

ⓘ
let none = WinFenceAssert::none();
let peer = win.remote(1)?;
win.fence(none, none, |_| Ok(()))?;
peer.read(0);
Ok(())
let none = WinFenceAssert::none();
win.fence(none, none, |_| Ok(()))?;
let peer = win.remote(1)?;
peer.read(0);
Ok(())

A view stays on the thread that owns its window, so its accesses are ordered against that thread’s MPI calls (a Relaxed access on another thread is not):

ⓘ
let local = win.local();
std::thread::scope(|s| {
    s.spawn(move || local.read(0));
});
let first = win.local().read(0);
std::thread::scope(|s| {
    s.spawn(move || first);
});

nor borrowed by one:

ⓘ
let local = win.local();
std::thread::scope(|s| {
    s.spawn(|| local.read(0));
});
let first = win.local().read(0);
std::thread::scope(|s| {
    s.spawn(|| first);
});

The window cannot be dropped while a view of it lives:

ⓘ
let win = Win::<u64>::allocate(world, 4)?;
let local = win.local();
drop(win);
local.read(0);
Ok(())
let win = Win::<u64>::allocate(world, 4)?;
let local = win.local();
local.read(0);
drop(win);
Ok(())

A slice borrows its view, so a handle’s slice cannot leave the closure either:

ⓘ
let mut keep: Option<&[u64]> = None;
win.lock_all(|e| {
    let view = e.local();
    // SAFETY: only the type system is under test, and it rejects this program.
    keep = Some(unsafe { view.as_slice() });
    Ok(())
})
win.lock_all(|e| {
    let mut keep: Option<&[u64]> = None;
    let view = e.local();
    // SAFETY: nothing writes the window while the slice lives.
    keep = Some(unsafe { view.as_slice() });
    Ok(())
})

One view hands out one &mut [T] at a time. The compiler checks only that view: the contract of WinView::as_mut_slice covers every other view, slice and RMA call that reaches the region.

ⓘ
let mut view = win.local();
// SAFETY: only the type system is under test, and it rejects this program.
let first = unsafe { view.as_mut_slice() };
let second = unsafe { view.as_mut_slice() };
first[0] = 1;
second[0] = 2;
let mut view = win.local();
// SAFETY: nothing else accesses the window while a slice lives.
let first = unsafe { view.as_mut_slice() };
first[0] = 1;
let second = unsafe { view.as_mut_slice() };
second[0] = 2;

§Freeing a window inside an epoch

MPI_Win_free is only valid once the caller has completed its RMA involvement (MPI-4.1 §12.2.5), so a window cannot be dropped inside its own epoch:

ⓘ
let mut win = Win::<u64>::allocate(world, 4)?;
let none = WinFenceAssert::none();
win.fence(none, none, |_| {
    drop(win);
    Ok(())
})
let mut win = Win::<u64>::allocate(world, 4)?;
let none = WinFenceAssert::none();
win.fence(none, none, |_| Ok(()))?;
drop(win);
Ok(())

and so cannot into_buffer, which takes the window by value:

ⓘ
let mut win = Win::<u64>::allocate(world, 4)?;
let none = WinFenceAssert::none();
win.fence(none, none, |_| {
    let _buf = win.into_buffer()?;
    Ok(())
})
let mut win = Win::<u64>::allocate(world, 4)?;
let none = WinFenceAssert::none();
win.fence(none, none, |_| Ok(()))?;
let _buf = win.into_buffer()?;
Ok(())

post opens an exposure epoch with no closure, so no borrow keeps the window alive through it. The window remembers the open epoch instead: until wait_exposure, or a test_exposure that returns true, closes it, into_buffer returns Error::InvalidState, and dropping the window leaks it, so Mpi skips MPI_Finalize. The test_rma_free_exposed_window example checks both. The epoch’s &mut borrow also keeps post out of a lock or lock_all closure, where MPI-4.1 §12.5.3 makes it erroneous:

ⓘ
win.lock_all(|_| {
    win.post(group, WinPscwAssert::none())
})
win.lock_all(|_| Ok(()))?;
win.post(group, WinPscwAssert::none())

§Creating a window

A buffer lent to Win::create could be dropped while MPI still exposes it, so create takes the Vec by value and into_buffer gives it back:

ⓘ
let mut buf = vec![0u64; 4];
let _win = Win::create(world, &mut buf)?;
Ok(())
let win = Win::create(world, vec![0u64; 4])?;
let _buf = win.into_buffer()?;
Ok(())

§Request-based operations

rput, rget and raccumulate exist only on the passive-target handle. A request borrows the origin for 's and its epoch’s registry, which completes every request before the unlock, so the origin cannot be a closure-local:

ⓘ
win.lock(LockType::Shared, 1, |e| {
    let origin = [1u64; 4];
    e.rput(&origin, 1, 0)?.wait()?;
    Ok(())
})
let origin = [1u64; 4];
win.lock(LockType::Shared, 1, |e| {
    e.rput(&origin, 1, 0)?.wait()?;
    Ok(())
})
ⓘ
win.lock(LockType::Shared, 1, |e| {
    let mut origin = [0u64; 4];
    e.rget(&mut origin, 1, 0)?.wait()?;
    Ok(())
})
let mut origin = [0u64; 4];
win.lock(LockType::Shared, 1, |e| {
    e.rget(&mut origin, 1, 0)?.wait()?;
    Ok(())
})
ⓘ
win.lock(LockType::Shared, 1, |e| {
    let origin = [1u64; 4];
    e.raccumulate(&origin, 1, 0, ReduceOp::Sum)?.wait()?;
    Ok(())
})
let origin = [1u64; 4];
win.lock(LockType::Shared, 1, |e| {
    e.raccumulate(&origin, 1, 0, ReduceOp::Sum)?.wait()?;
    Ok(())
})

A request cannot leave the closure either, stored outside:

ⓘ
let origin = [1u64; 4];
let mut keep = None;
win.lock(LockType::Shared, 1, |e| {
    keep = Some(e.rput(&origin, 1, 0)?);
    Ok(())
})
let origin = [1u64; 4];
win.lock(LockType::Shared, 1, |e| {
    let mut keep = None;
    keep = Some(e.rput(&origin, 1, 0)?);
    Ok(())
})

or returned:

ⓘ
let origin = [1u64; 4];
let _kept = win.lock(LockType::Shared, 1, |e| e.rput(&origin, 1, 0))?;
Ok(())
let origin = [1u64; 4];
let _done = win.lock(LockType::Shared, 1, |e| e.rput(&origin, 1, 0)?.wait())?;
Ok(())

A fence or start epoch has no request-based operations at all:

ⓘ
let none = WinFenceAssert::none();
let origin = [1u64; 4];
win.fence(none, none, |e| {
    e.rput(&origin, 1, 0)?;
    Ok(())
})
let none = WinFenceAssert::none();
let origin = [1u64; 4];
win.fence(none, none, |e| {
    e.put(&origin, 1, 0)?;
    Ok(())
})

compare_and_swap is rejected on a window of floats, where AtomicMpiDatatype documents it.

§What the compiler does not check

  • A Win that is forgotten leaks its buffer instead of freeing it, and so does one dropped after Mpi skipped MPI_Finalize (the test_rma_forget_window example). Mpi dropped inside an epoch still lets the epoch complete and close (the test_rma_epoch_drop_mpi example).
  • A peer’s collective free waits for every rank, so it can block until the job ends when a rank leaks its window instead of freeing it, whether by forgetting it, through a refused or failed free, or through an open exposure epoch. Likewise an origin’s unlock or complete can wait for a target that has stopped calling MPI (MPI-4.1 §12.7.3).
  • The NOPUT, NOSTORE and NOCHECK assertions are the caller’s contract (MPI-4.1 §12.5.5). A broken NOPUT can let a peer’s write land after the target’s closing call, possibly in a buffer into_buffer has already handed back; a broken NOCHECK can let an access land before the epoch opens; a broken NOSTORE can let a peer read stale data.
  • A window locked and exposed at once, by post before lock or lock_all or by a peer’s lock during an exposure epoch, is erroneous (MPI-4.1 §12.5.3). The open exposure epoch still keeps the window from being freed.
  • A fence opened while this rank’s post exposure epoch is open is erroneous (MPI-4.1 §12.5: distinct exposure epochs on one window must be disjoint). MPICH 4.2.3 rejects it with MPI_ERR_RMA_SYNC on the opening fence.
  • A panic in a fence or start closure aborts the process, because the closing call is collective or synchronizing, and one in a lock or lock_all closure unwinds after the unlock. Both rely on unwinding: under panic = "abort" the process stops at the panic itself, before any closing call, but with Rust’s message instead of the crate’s, and the test_rma_epoch_panic example, which checks that message, needs the default panic = "unwind".

§Example

use ferrompi::{Mpi, Win};

let mpi = Mpi::init().unwrap();
let world = mpi.world();

// Create a window over a buffer it owns until MPI_Win_free
let win = Win::create(&world, vec![0i32; 16]).unwrap();
assert_eq!(win.comm_size(), world.size());
drop(win); // MPI_Win_free called here

pub fn create(comm: &Communicator, buf: Vec<T>) -> Result<Self>

Create an RMA window over a buffer the window then owns.

Wraps MPI_Win_create. The window takes buf and keeps it, neither resized nor borrowed, until MPI_Win_free has succeeded (see into_buffer and the type’s # Dropping section), so no safe call can free or reuse memory a peer may still access. Reach it with local. buf is consumed on every return: dropped if MPI created no window, leaked if it did and the window cannot be returned.

disp_unit is set to size_of::<T>() and size to buf.len() * size_of::<T>(). Creation first exchanges each rank’s displacement unit and exposed length with one allgather over comm.

§Arguments
  • comm - Communicator; all processes must call this collectively.
  • buf - The vector that forms this process’s local window memory.
§Errors

Returns an error if:

  • Any rank’s buf exposed byte length does not fit in 56 bits (Error::InvalidArgument on every rank).
  • The length exchange fails (Error::Mpi with operation: Some("allgather")); this can happen on some ranks only, and the other ranks can then block creating the window.
  • The call is refused after the length exchange (Error::Finalized or Error::ThreadLevelViolation, as those variants describe): no window is created on this rank, and the other ranks can then block creating the window.
  • The MPI call fails (Error::Mpi with operation: Some("win_create")).
  • The window table is full (Error::ResourceExhausted; the window is then leaked: never freed, and counted as alive so Mpi skips MPI_Finalize, and the buffer is leaked with it).

In the last case, a peer whose own call succeeded blocks in its collective free (MPI_Win_free) waiting for this rank.

§Example
use ferrompi::{Mpi, Win};

let mpi = Mpi::init().unwrap();
let world = mpi.world();
let win = Win::create(&world, vec![0f64; 64]).unwrap();

pub fn allocate(comm: &Communicator, local_count: usize) -> Result<Self>

Allocate an RMA window with MPI-managed memory.

Wraps MPI_Win_allocate. MPI allocates local_count elements of type T for this process. The allocation is freed automatically when the window is dropped (via MPI_Win_free).

disp_unit is set to size_of::<T>() and size to local_count * size_of::<T>(). Creation first exchanges each rank’s displacement unit and exposed length with one allgather over comm.

The local segment reads as zero when the call returns.

§Arguments
  • comm - Communicator; all processes must call this collectively.
  • local_count - Number of T elements to allocate for this process. Zero is allowed; a valid window with a dangling base pointer is returned.
§Errors

Returns an error if:

  • Any rank’s local_count exposed byte length does not fit in 56 bits (Error::InvalidArgument on every rank).
  • The length exchange fails (Error::Mpi with operation: Some("allgather")); this can happen on some ranks only, and the other ranks can then block creating the window.
  • The call is refused after the length exchange (Error::Finalized or Error::ThreadLevelViolation, as those variants describe): no window is created on this rank, and the other ranks can then block creating the window.
  • The MPI call fails (Error::Mpi with operation: Some("win_allocate")); this can happen on some ranks only, and the other ranks can then block in the barrier after the new segment is zeroed.
  • The window table is full (Error::ResourceExhausted; the window is then leaked: never freed, and counted as alive so Mpi skips MPI_Finalize).
  • An error occurs while zeroing the new segment (Error::Mpi with operation: Some("win_allocate"); the window is then leaked: never freed, and counted as alive so Mpi skips MPI_Finalize).
  • MPI returns a null pointer for a non-zero count (Error::Internal; the window is then leaked: never freed, and counted as alive so Mpi skips MPI_Finalize).

In the last three cases, a peer whose own call succeeded blocks in its collective Drop (MPI_Win_free) waiting for this rank.

§Example
use ferrompi::{Mpi, Win};

let mpi = Mpi::init().unwrap();
let world = mpi.world();
let win = Win::<f64>::allocate(&world, 32).unwrap();

pub fn allocate_shared(comm: &Communicator, local_count: usize) -> Result<Self>

Allocate a shared-memory RMA window.

Wraps MPI_Win_allocate_shared. MPI allocates local_count elements of type T for this process, in memory every process of comm can load and store directly. comm must be a shared-memory communicator, such as one from Communicator::split_shared, and the call is collective over it. Every rank must pass an element type of one size: creation checks this with the length exchange and refuses a mismatch on every rank. MPI aligns the first non-empty segment for any predefined datatype and places the others after it, so every base is then aligned for T (MPI-4.1 §9.2, p.447; MPI-4.1 §12.2.3, p.555-556).

disp_unit is set to size_of::<T>() and size to local_count * size_of::<T>(). Creation first exchanges each rank’s displacement unit and exposed length with one allgather over comm, and then queries every rank’s region once with MPI_Win_shared_query, so remote makes no MPI call.

The local segment reads as zero when the call returns.

The window is an ordinary Win: every epoch, view and transfer works on it. remote returns Error::NotSupported unless MPI reports the window’s memory model as MPI_WIN_UNIFIED, because MPI does not define the semantics of accessing shared window memory directly in the separate memory model (MPI-4.1 §12.2.3, p.558). local works in either model.

§Arguments
  • comm - A shared-memory communicator; all processes must call this collectively.
  • local_count - Number of T elements to allocate for this process. Zero is allowed: the region is then empty, whatever pointer MPI returns for it.
§Errors

Returns an error if:

  • Ranks passed element types of different sizes (Error::InvalidArgument with arg: "T" on every rank, before any window is created).
  • Any rank’s local_count exposed byte length does not fit in 56 bits (Error::InvalidArgument on every rank).
  • The length exchange fails (Error::Mpi with operation: Some("allgather")); this can happen on some ranks only, and the other ranks can then block creating the window.
  • The call is refused after the length exchange (Error::Finalized or Error::ThreadLevelViolation, as those variants describe): no window is created on this rank, and the other ranks can then block creating the window.
  • The MPI call fails (Error::Mpi with operation: Some("win_allocate_shared")); this can happen on some ranks only, and the other ranks can then block in the barrier after the new segment is zeroed.
  • The window table is full (Error::ResourceExhausted; the window is then leaked: never freed, and counted as alive so Mpi skips MPI_Finalize).
  • An error occurs while zeroing the new segment (Error::Mpi with operation: Some("win_allocate_shared"); the window is then leaked: never freed, and counted as alive so Mpi skips MPI_Finalize).
  • MPI returns a null pointer for a non-zero count (Error::Internal; the window is then leaked: never freed, and counted as alive so Mpi skips MPI_Finalize).
  • Querying a rank’s region fails (Error::Mpi with operation: Some("win_shared_query")), or returns a null pointer for a non-zero size (Error::Internal); the window is then leaked, as above.

In the last four cases, a peer whose own call succeeded blocks in its collective Drop (MPI_Win_free) waiting for this rank.

§Example

Each rank stores through its own view and reads a peer’s region through remote, inside one lock_all closure: store, sync, synchronize the processes, sync, load (MPI-4.1 §12.7, p.609; Example 12.23, p.622).

use ferrompi::{Mpi, Win};

let mpi = Mpi::init().unwrap();
let node = mpi.world().split_shared().unwrap();
let mut win = Win::<u64>::allocate_shared(&node, 4).unwrap();
let peer = (node.rank() + 1) % node.size();
win.lock_all(|e| {
    e.local().write(0, node.rank() as u64 + 1);
    e.sync()?;
    node.barrier()?;
    e.sync()?;
    let _seen = e.remote(peer)?.read(0);
    Ok(())

pub fn into_buffer(self) -> Result<Option<Vec<T>>>

Free the window and return its buffer.

Calls MPI_Win_free and, once it has succeeded, returns the vector Win::create took, or None for a Win::allocate or Win::allocate_shared window (MPI frees its memory with the window). Unlike Drop, it reports a failed or refused free.

The call is collective: it can block until every peer has called MPI_Win_free, because MPI-4.1 §12.2.5 requires it to wait until every passive-target access to this rank has completed. An error can reach some ranks only. A rank whose free failed, or was refused, leaks its buffer and keeps the window counted as alive; a peer whose free succeeded gets its buffer back; a peer that never calls the free blocks in its own.

§Errors
  • Error::InvalidState while an exposure epoch opened by post is open, because a peer may still write into the window (MPI-4.1 §12.2.5): no MPI call is made. The call takes the window, so the refusal drops it, which leaks the window and its buffer and keeps the window counted as alive. Close the epoch with wait_exposure or a test_exposure that returns true first.
  • Error::Finalized once Mpi is being dropped: no MPI call is made and the buffer is leaked.
  • Error::ThreadLevelViolation in a debug build at ThreadLevel::Serialized when the call overlaps another thread’s MPI call: no MPI call is made, and the window and its buffer are leaked and stay counted, so Mpi skips MPI_Finalize.
  • Error::Mpi with operation: Some("win_free") if the free fails: the buffer is leaked and the window stays counted as alive, so Mpi skips MPI_Finalize.
§Example
use ferrompi::{Mpi, Win};

let mpi = Mpi::init().unwrap();
let world = mpi.world();
let win = Win::create(&world, vec![0f64; 64]).unwrap();
win.local().write(0, 1.5);
let buf = win.into_buffer().unwrap().expect("Win::create owns its buffer");
assert_eq!(buf[0], 1.5);

pub fn local(&self) -> WinView<'_, T>

A view of this process’s window memory.

The view reads and writes elements with Relaxed atomic accesses, which stay sound while a peer’s put or accumulate writes the same memory (see WinView). No safe &[T] is offered, because the compiler may assume a slice does not change while it is borrowed.

The view borrows the window, so it cannot outlive it, and cannot be held across an epoch, which borrows the window mutably. Inside an epoch, take the view from the handle with ActiveEpoch::local or PassiveEpoch::local.

A put or accumulate that a fence or wait_exposure at this process completed is visible when that call returns. One that a peer completed by its unlock or flush is guaranteed visible only after this process’s next fence, wait_exposure, lock or lock_all on the window, or sync inside a passive-target epoch (MPI-4.1 §12.7, rules 2 to 4 and 6, p.606).

§Example
use ferrompi::{Mpi, Win};

let mpi = Mpi::init().unwrap();
let world = mpi.world();
let win = Win::<u64>::allocate(&world, 4).unwrap();
let local = win.local();
local.write(0, 7);
assert_eq!(local.read(0), 7);

pub fn remote(&self, rank: i32) -> Result<WinView<'_, T>>

A view of rank’s region of this shared window.

The regions of a Win::allocate_shared window were queried once at creation, so this makes no MPI call: the view holds the address and length of that rank’s region in this process. Its accesses are the Relaxed atomic ones of WinView, and it borrows the window as local’s does. Inside an epoch, take the view from the handle with ActiveEpoch::remote or PassiveEpoch::remote.

remote(own rank) addresses the same memory as local, so the two views alias: a store through one is read through the other, and the contract of WinView::as_mut_slice covers it.

Every rank’s T has one size, which Win::allocate_shared checks. A peer that passed another type of that size (f64 against u64, say) wrote bits that read back as this rank’s T, and every bit pattern is a valid element.

§Publication

A store, put or accumulate by another process is guaranteed to be visible to this process’s loads of the region only after MPI synchronization; on coherent hardware it may be seen earlier. MPI_Win_wait at this process never publishes a peer’s region: it completes the exposure epoch of this process’s own region. A fence publishes what was written before the previous fence. That fence completes puts and accumulates at the region’s owner, and makes stores to shared memory visible, before it returns there (MPI-4.1 §12.5.1, p.591; §12.7, rule 2, p.606). The next fence synchronizes unless it carries MPI_MODE_NOPRECEDE (p.592), so it returns at this process only after the owner has entered it. Otherwise a reader needs the passive-target route: the writer’s sync after its stores, or its unlock or flush after its puts and accumulates, then process synchronization, then sync at this process inside a passive-target epoch (MPI-4.1 §12.5.4, p.603; the advice to users after rule U5, MPI-4.1 §12.7, p.609; Example 12.23, p.622). The same holds for a slice of the view, WinView::as_slice.

§Errors
  • Error::NotSupported if this window is not from Win::allocate_shared, or MPI did not report its memory model as MPI_WIN_UNIFIED, which MPI requires for direct access to shared window memory (MPI-4.1 §12.2.3, p.558).
  • Error::InvalidArgument with arg: "rank" if rank is not a rank of the window’s communicator.
§Example
use ferrompi::{Mpi, Win};

let mpi = Mpi::init().unwrap();
let node = mpi.world().split_shared().unwrap();
let win = Win::<u64>::allocate_shared(&node, 4).unwrap();
let own = win.remote(node.rank()).unwrap();
own.write(0, 7);
assert_eq!(win.local().read(0), 7);

pub fn fence<'env, R>( &mut self, open: WinFenceAssert, close: WinFenceAssert, f: impl for<'s> FnOnce(&'s ActiveEpoch<'s, 'env, T>) -> Result<R>, ) -> Result<R>

Run a closure in a fence epoch (active-target synchronization).

Wraps MPI_Win_fence, which is collective over this window’s communicator: every rank calls fence at the same logical program point. The call opens the epoch with a fence carrying open, runs f with the epoch’s ActiveEpoch, and closes it with a fence carrying close, whether f returned Ok or Err, so every rank makes the closing collective call. When it returns, the RMA operations f issued are complete at this rank, and visible at each target once that target’s closing fence returns.

§Arguments
  • open — Assertion hint bitmask of the opening fence. Use WinFenceAssert::none() when no hints are needed. Compose multiple hints with |. WinFenceAssert::no_succeed() is rejected.
  • close — Assertion hint bitmask of the closing fence. WinFenceAssert::no_precede() is rejected.
  • f — The closure that issues the epoch’s RMA operations.
§Errors
  • Error::InvalidArgument with arg: "open" if open carries no_succeed, and with arg: "close" if close carries no_precede; no MPI call is made. Either would let MPI keep using an origin buffer after the closing fence returned (MPI-4.1 §12.5.5).
  • Error::Finalized once Mpi is being dropped: the opening fence is refused and f does not run.
  • Error::Mpi with operation: Some("win_fence") if the opening fence fails (f does not run) or the closing fence fails.

When f returns an error, that error is returned in place of a closing fence’s. MPI ran the closing fence, and the crate trusts that it completed or failed the epoch’s operations, as MPICH and Open MPI do; MPI-4.1 §9.4 (p.460) does not promise it.

§Aborts

A panic in f aborts the process: the closing fence is collective, and one rank closing it alone can hang or mismatch the job. A closing fence refused before MPI ran it also aborts, since the epoch’s origin buffers are still in MPI’s hands; in a debug build at ThreadLevel::Serialized, an overlap with another thread’s MPI call is the one way to reach that.

§Example
use ferrompi::{Mpi, Win, WinFenceAssert};

let mpi = Mpi::init().unwrap();
let world = mpi.world();
let mut win = Win::<f64>::allocate(&world, 16).unwrap();

win.fence(WinFenceAssert::none(), WinFenceAssert::none(), |_epoch| {
    // ... RMA operations would go here ...
    Ok(())
})
.unwrap();

pub fn post(&self, group: &Group, assert: WinPscwAssert) -> Result<()>

Start an exposure epoch (active-target PSCW synchronization).

Wraps MPI_Win_post. This rank exposes its window memory to the ranks in group, which are expected to run Win::start. Close the exposure epoch with Win::wait_exposure or Win::test_exposure.

The exposure epoch has no handle: this rank issues no RMA call in it. While it is open, a peer may still write into this window, so into_buffer is refused and dropping the window leaks it instead of freeing it (MPI-4.1 §12.2.5; see the type’s # Dropping section).

§Arguments
  • group — The group of ranks that will issue RMA operations against this rank’s window.
  • assert — Assertion hint bitmask. Use WinPscwAssert::default() (or WinPscwAssert::none()) when no optimization hints are needed.
§Errors
  • Error::Finalized or Error::ThreadLevelViolation if the call is refused before MPI runs it: no exposure epoch opens.
  • Error::Mpi { operation: Some("win_post"), .. } if MPI reports an error. The exposure epoch then counts as open, because a post that failed may still have opened it (MPI-4.1 §9.4, p.460).
§Example
use ferrompi::{Mpi, Win, WinPscwAssert};

let mpi = Mpi::init().unwrap();
let world = mpi.world();
let win = Win::<f64>::allocate(&world, 8).unwrap();
let access_group = world.group().unwrap().include(&[1]).unwrap();

// Rank 0 exposes its window to rank 1
win.post(&access_group, WinPscwAssert::default()).unwrap();
win.wait_exposure().unwrap();

pub fn start<'env, R>( &mut self, group: &Group, assert: WinPscwAssert, f: impl for<'s> FnOnce(&'s ActiveEpoch<'s, 'env, T>) -> Result<R>, ) -> Result<R>

Run a closure in a PSCW access epoch (active-target synchronization).

Wraps MPI_Win_start and MPI_Win_complete. This rank will issue RMA operations against the ranks in group, which must have called (or will call) Win::post. The call translates group into ranks of the window’s communicator, once, as the epoch’s access set: a transfer to any other rank returns an error (see ActiveEpoch). It then opens the epoch, runs f with the epoch’s ActiveEpoch, and closes it with MPI_Win_complete, whether f returned Ok or Err, so the target ranks’ Win::wait_exposure never waits on an epoch left open. When it returns, the RMA operations f issued are complete at the origin.

§Arguments
  • group — The group of ranks that have called or will call Win::post.
  • assert — Assertion hint bitmask. Use WinPscwAssert::default() when no optimization hints are needed.
  • f — The closure that issues the epoch’s RMA operations.
§Errors
  • Error::Finalized once Mpi is being dropped: the epoch is not opened and f does not run.
  • Error::InvalidArgument with arg: "group" if a member of group is not a rank of the window’s communicator; no MPI call opens the epoch and f does not run.
  • Error::ResourceExhausted with resource ResourceKind::Group if the group table has no slot for the window’s group, which the translation needs briefly (f does not run).
  • Error::Mpi with operation: Some("win_get_group"), Some("group_size") or Some("group_translate_ranks") if translating group fails (f does not run).
  • Error::Mpi with operation: Some("win_start") if opening the epoch fails (f does not run).
  • Error::Mpi with operation: Some("win_complete") if closing it fails.

When f returns an error, that error is returned in place of MPI_Win_complete’s. MPI ran the call, and the crate trusts that it completed or failed the epoch’s operations, as MPICH and Open MPI do; MPI-4.1 §9.4 (p.460) does not promise it.

§Aborts

A panic in f aborts the process: closing the epoch synchronizes with the target ranks, and one rank closing it alone can hang or mismatch the job. An MPI_Win_complete refused before MPI ran it also aborts, since the epoch’s origin buffers are still in MPI’s hands; in a debug build at ThreadLevel::Serialized, an overlap with another thread’s MPI call is the one way to reach that.

§Example
use ferrompi::{Mpi, Win, WinPscwAssert};

let mpi = Mpi::init().unwrap();
let world = mpi.world();
let mut win = Win::<f64>::allocate(&world, 8).unwrap();
let exposure_group = world.group().unwrap().include(&[0]).unwrap();

// Rank 1 opens an access epoch to rank 0's window
win.start(&exposure_group, WinPscwAssert::default(), |_epoch| {
    // ... RMA operations would go here ...
    Ok(())
})
.unwrap();

pub fn wait_exposure(&self) -> Result<()>

Wait for the exposure epoch to close (active-target PSCW synchronization).

Wraps MPI_Win_wait. Blocks until all RMA operations issued by the access group (those that ran Win::start) against this rank’s window are complete. Closes the exposure epoch opened by Win::post, which has no handle: this rank issues no RMA call in it. A successful call lets into_buffer free the window again.

§Errors

Returns Error::Mpi { operation: Some("win_wait"), .. } if MPI reports an error; the exposure epoch then counts as still open.

§Example
win.post(&g, WinPscwAssert::default()).unwrap();
// ... wait for remote access to complete ...
win.wait_exposure().unwrap();

pub fn test_exposure(&self) -> Result<bool>

Nonblocking test for exposure epoch completion (active-target PSCW).

Wraps MPI_Win_test. Returns true if the exposure epoch started by Win::post has completed (i.e., all access-side ranks have closed their Win::start epochs), false otherwise. Does not block. That exposure epoch has no handle: this rank issues no RMA call in it. A call that returns true lets into_buffer free the window again.

Returns Error::Mpi { operation: Some("win_test"), .. } if MPI reports an error; the exposure epoch then counts as still open.

§Example
win.post(&g, WinPscwAssert::default()).unwrap();
// Polling loop (in practice, do useful work between tests)
while !win.test_exposure().unwrap() {
    // do other work
}

pub fn lock<'env, R>( &mut self, lock_type: LockType, rank: i32, f: impl for<'s> FnOnce(&'s PassiveEpoch<'s, 'env, T>) -> Result<R>, ) -> Result<R>

Run a closure in a passive-target epoch on one rank’s window.

Wraps MPI_Win_lock and MPI_Win_unlock. The call locks rank’s window, which gives one-sided access to that rank’s memory without its active participation, runs f with the epoch’s PassiveEpoch, and unlocks the window, whether f returned Ok, returned Err or panicked. Before it unlocks, it completes every request f left pending. When it returns, the RMA operations f issued are complete at this rank and at rank (MPI-4.1 §12.5.3), so the origin buffers they borrowed stay borrowed until the unlock has returned. rank is the epoch’s access set: a transfer to another rank returns an error (see PassiveEpoch).

§Arguments
  • lock_type - LockType::Exclusive for read-write access, or LockType::Shared for concurrent read-only access with other shared lockers.
  • rank - The target rank to lock (0-based, within the window’s communicator).
  • f - The closure that issues the epoch’s RMA operations.
§Errors
  • Error::Finalized once Mpi is being dropped: the epoch is not opened and f does not run.
  • Error::Mpi with operation: Some("win_lock") if the lock fails, for example when MPI rejects rank (f does not run).
  • Error::Mpi with operation: Some("lock") if a request f left pending fails when the epoch completes it; the unlock still runs.
  • Error::Mpi with operation: Some("win_unlock") if the unlock fails.

When f returns an error, that error is returned in place of a request’s and the unlock’s. MPI ran the unlock, and the crate trusts that it completed or failed the epoch’s operations, as MPICH and Open MPI do; MPI-4.1 §9.4 (p.460) does not promise it.

§Panics

A passive-target epoch is not collective: MPI_Win_unlock completes this rank’s operations and needs no matching call at any other rank, though it can wait until the target makes MPI progress (MPI-4.1 §12.7.3). A panic in f therefore completes the pending requests, unlocks the window and then continues unwinding, as scope does; an open fence or PSCW epoch aborts instead. An error from completing the requests or from that unlock is dropped.

§Aborts

An MPI_Win_unlock refused before MPI ran it aborts the process, since the epoch’s origin buffers are still in MPI’s hands; so does a wait for the pending requests that completes none of them. In a debug build at ThreadLevel::Serialized, an overlap with another thread’s MPI call is the one way to reach either.

§Example
use ferrompi::{LockType, Mpi, Win};

let mpi = Mpi::init().unwrap();
let world = mpi.world();
let mut win = Win::<f64>::allocate(&world, 8).unwrap();

win.lock(LockType::Shared, 0, |e| {
    e.flush(0)?;
    e.flush_local(0)?;
    Ok(())
})
.unwrap();

pub fn lock_all<'env, R>( &mut self, f: impl for<'s> FnOnce(&'s PassiveEpoch<'s, 'env, T>) -> Result<R>, ) -> Result<R>

Run a closure in a passive-target epoch on every rank’s window.

Wraps MPI_Win_lock_all and MPI_Win_unlock_all. The call acquires shared locks on all ranks in the window’s communicator, runs f with the epoch’s PassiveEpoch, and releases them, whether f returned Ok, returned Err or panicked. Before it unlocks, it completes every request f left pending. It gives concurrent access to every rank’s window memory in one epoch, without a lock and an unlock per rank, and every rank is in the epoch’s access set. When it returns, the RMA operations f issued are complete at this rank and at their targets (MPI-4.1 §12.5.3), so the origin buffers they borrowed stay borrowed until the unlock has returned.

§Arguments
  • f - The closure that issues the epoch’s RMA operations.
§Errors
  • Error::Finalized once Mpi is being dropped: the epoch is not opened and f does not run.
  • Error::Mpi with operation: Some("win_lock_all") if the lock fails (f does not run).
  • Error::Mpi with operation: Some("lock_all") if a request f left pending fails when the epoch completes it; the unlock still runs.
  • Error::Mpi with operation: Some("win_unlock_all") if the unlock fails.

When f returns an error, that error is returned in place of a request’s and the unlock’s, as for Win::lock.

§Panics

A panic in f unlocks the window and then continues unwinding, as for Win::lock.

§Aborts

An MPI_Win_unlock_all refused before MPI ran it, and a wait for the pending requests that completes none of them, abort the process, as for Win::lock.

§Example
use ferrompi::{Mpi, Win};

let mpi = Mpi::init().unwrap();
let world = mpi.world();
let mut win = Win::<f64>::allocate(&world, 8).unwrap();

win.lock_all(|e| {
    e.flush_all()?;
    e.flush_local_all()?;
    e.sync()?;
    Ok(())
})
.unwrap();
