Expand description

The handle an active-target access epoch gives its closure.

Win::fence and Win::start open an epoch, run a closure with this handle, and close the epoch when the closure returns, whether it returned Ok or Err, with the epoch’s closing call: the closing fence of Win::fence, or MPI_Win_complete of Win::start. The epoch is open exactly while the closure runs, and the window is mutably borrowed for that time.

§Lifetimes

The handle carries the invariant lifetimes of Scope: 's is the epoch, and 'env outlives it. put, get, accumulate, get_accumulate, fetch_and_op and compare_and_swap borrow their buffers for 's, so a buffer outlives the closing call, which is when MPI stops using it, and cannot be dropped or written before then. A buffer MPI writes (a get destination or a result) cannot be read before then either. These six methods reject a buffer declared inside the closure, because it is freed before then. Declare buffers before the call to fence or start. local and remote return views that borrow the handle, so they cannot leave the closure.

§Access set

A transfer’s target_rank must be a rank the epoch gives access to: every rank of the window’s communicator for Win::fence, the members of the group for Win::start. Any other rank returns Error::InvalidArgument with arg: "target_rank" and makes no MPI call, because MPI-4.1 §12.5 makes such a transfer erroneous and its closing call would not complete it.

§Thread safety

ActiveEpoch is neither Send nor Sync: it borrows a Win, which is neither.

pub fn local(&self) -> WinView<'_, T>

A view of this process’s window memory, as Win::local, taken through the handle: the window itself is borrowed mutably while the closure runs.

The view borrows the handle, so it cannot leave the closure. An access that conflicts with a peer’s put or accumulate to the same location has an unspecified result, as WinView describes.

Source

pub fn remote(&self, rank: i32) -> Result<WinView<'_, T>>

A view of rank’s region of a shared window, as Win::remote, taken through the handle: the window itself is borrowed mutably while the closure runs.

The view borrows the handle, so it cannot leave the closure. It makes no MPI call, and the epoch’s access set does not restrict it: loads and stores of shared memory need no access epoch to that rank. What publishes a peer’s writes is described under Win::remote’s # Publication. Inside a fence epoch, the view reads what was written before the fence that preceded this epoch’s opening fence (in an earlier fence epoch, say), provided the opening fence does not carry MPI_MODE_NOPRECEDE. A peer’s stores made inside this epoch are not ordered with this process’s loads.

§Errors

As Win::remote.

pub fn put( &self, origin: &'s [T], target_rank: i32, target_disp: i64, ) -> Result<()>

One-sided write: copy origin into the remote rank’s window memory.

Wraps MPI_Put. The operation is posted at once, but it completes only when the epoch’s closing call returns, and the data is visible at the target once the target’s own closing call returns.

The count is origin.len(); pass a sub-slice for a shorter transfer.

§Arguments
  • origin — Local buffer whose contents are written to the target.
  • target_rank — Destination rank (0-based, within this window’s communicator).
  • target_disp — Displacement at the target, measured in units of disp_unit (i.e., multiples of size_of::<T>()).
§Errors
  • Error::InvalidArgument — if target_rank is not a rank of the window’s communicator (including -1) or of the epoch’s access set (arg: "target_rank"), target_disp is negative, or the access does not fit in the target rank’s window; no MPI call is made.
  • Error::Finalized — once Mpi is being dropped.
  • Error::Mpi — if MPI_Put fails; on MPI before 4.0 this includes class Count for an origin of more than i32::MAX elements.
§Example
use ferrompi::{Mpi, Win, WinFenceAssert};

fn main() -> ferrompi::Result<()> {
    let mpi = Mpi::init()?;
    let world = mpi.world();
    let mut win = Win::<f64>::allocate(&world, 4)?;
    let buf = [1.0f64, 2.0, 3.0, 4.0];

    // `buf` is declared before the epoch: MPI may read it until the
    // closing fence returns
    win.fence(WinFenceAssert::none(), WinFenceAssert::none(), |e| {
        // Rank 0 puts four elements into rank 1's window at displacement 0
        if world.rank() == 0 {
            e.put(&buf, 1, 0)?;
        }
        Ok(())
    })?;

    // The epoch is closed: rank 1's window holds the data
    if world.rank() == 1 {
        let mut seen = [0.0f64; 4];
        win.local().copy_to_slice(&mut seen);
        assert_eq!(seen, buf);
    }
    Ok(())
}

pub fn get( &self, origin: &'s mut [T], target_rank: i32, target_disp: i64, ) -> Result<()>

One-sided read: copy data from a remote rank’s window memory into origin.

Wraps MPI_Get. The operation is posted at once, but origin holds the data only after the epoch’s closing call returns, and stays borrowed until then, so it cannot be read earlier.

The count is origin.len(); pass a sub-slice for a shorter transfer.

§Arguments
  • origin — Local destination buffer filled by the remote read.
  • target_rank — Source rank (0-based, within this window’s communicator).
  • target_disp — Displacement at the target, measured in units of disp_unit (i.e., multiples of size_of::<T>()).
§Errors
  • Error::InvalidArgument — if target_rank is not a rank of the window’s communicator (including -1) or of the epoch’s access set (arg: "target_rank"), target_disp is negative, or the access does not fit in the target rank’s window; no MPI call is made.
  • Error::Finalized — once Mpi is being dropped.
  • Error::Mpi — if MPI_Get fails; on MPI before 4.0 this includes class Count for an origin of more than i32::MAX elements.
§Example
use ferrompi::{Mpi, Win, WinFenceAssert};

fn main() -> ferrompi::Result<()> {
    let mpi = Mpi::init()?;
    let world = mpi.world();
    let mut win = Win::<f64>::allocate(&world, 4)?;
    let mut buf = [0.0f64; 4];

    // Rank 1 initialises its window
    if world.rank() == 1 {
        win.local().copy_from_slice(&[1.0, 2.0, 3.0, 4.0]);
    }

    // `buf` is declared before the epoch: MPI may write it until the
    // closing fence returns
    win.fence(WinFenceAssert::none(), WinFenceAssert::none(), |e| {
        // Rank 0 reads four elements from rank 1's window at displacement 0
        if world.rank() == 0 {
            e.get(&mut buf, 1, 0)?;
        }
        Ok(())
    })?;

    // The epoch is closed: rank 0's buffer holds the data
    if world.rank() == 0 {
        assert_eq!(buf, [1.0, 2.0, 3.0, 4.0]);
    }
    Ok(())
}

pub fn accumulate( &self, origin: &'s [T], target_rank: i32, target_disp: i64, op: impl Into<AccumulateOp>, ) -> Result<()>

One-sided reduce-accumulate: combine data from a local origin buffer with a remote rank’s window memory using a reduction operation.

Wraps MPI_Accumulate. The operation is posted at once, but its effect at the target is visible only after the epoch’s closing call returns and the target’s own closing call returns.

op is a ReduceOp or AccumulateOp::REPLACE (like MPI_Put, but element-wise atomic); a user op is not accepted (MPI-4.1 §12.3.4). Under the default accumulate_ops window info value, same_op_no_op (MPI-4.1 §12.2.1), concurrent accumulates to one target location must use the same op or MPI_NO_OP, so mixing AccumulateOp::REPLACE and ReduceOp::Sum on one location is erroneous, and no type prevents it.

The count is origin.len(); pass a sub-slice for a shorter transfer.

§Arguments
  • origin — Local source buffer (read-only).
  • target_rank — Destination rank (0-based, within this window’s communicator).
  • target_disp — Displacement at the target, measured in units of disp_unit (i.e., multiples of size_of::<T>()).
  • op — Reduction operation to apply.
§Errors
  • Error::InvalidArgument with arg: "op" — if op is a predefined op MPI does not define on T (a bitwise or logical op on f32/f64); no MPI call is made.
  • Error::InvalidArgument — if target_rank is not a rank of the window’s communicator (including -1) or of the epoch’s access set (arg: "target_rank"), target_disp is negative, or the access does not fit in the target rank’s window; no MPI call is made.
  • Error::Finalized — once Mpi is being dropped.
  • Error::Mpi — if MPI_Accumulate fails for any other reason; on MPI before 4.0 this includes class Count for an origin of more than i32::MAX elements.
§Example
use ferrompi::{Mpi, ReduceOp, Win, WinFenceAssert};

fn main() -> ferrompi::Result<()> {
    let mpi = Mpi::init()?;
    let world = mpi.world();
    let mut win = Win::<f64>::allocate(&world, 4)?;
    let buf = [10.0f64, 20.0, 30.0, 40.0];

    // Rank 1 initialises its window
    if world.rank() == 1 {
        win.local().copy_from_slice(&[1.0, 2.0, 3.0, 4.0]);
    }

    // `buf` is declared before the epoch: MPI may read it until the
    // closing fence returns
    win.fence(WinFenceAssert::none(), WinFenceAssert::none(), |e| {
        // Rank 0 adds [10, 20, 30, 40] to rank 1's window
        if world.rank() == 0 {
            e.accumulate(&buf, 1, 0, ReduceOp::Sum)?;
        }
        Ok(())
    })?;

    // The epoch is closed: rank 1's window holds the sums
    if world.rank() == 1 {
        let mut seen = [0.0f64; 4];
        win.local().copy_to_slice(&mut seen);
        assert_eq!(seen, [11.0, 22.0, 33.0, 44.0]);
    }
    Ok(())
}

pub fn get_accumulate( &self, origin: &'s [T], result: &'s mut [T], target_rank: i32, target_disp: i64, op: impl Into<FetchOp>, ) -> Result<()>

Atomic read-modify-write: fetch the pre-update remote value into result, then apply op(origin, target_old) at the target, each element atomically with respect to other accumulate operations on that location (MPI-4.1 §12.7.1).

Wraps MPI_Get_accumulate. The operation is posted at once, but result holds the fetched values only after the epoch’s closing call returns, and the update is visible at the target once the target’s own closing call returns. result stays borrowed until then, so it cannot be read earlier.

op is a ReduceOp, FetchOp::NO_OP or FetchOp::REPLACE; a user op is not accepted (MPI-4.1 §12.3.4). FetchOp::NO_OP is the canonical “atomic get” pattern: result receives the target’s current value and the target memory is left unchanged; origin’s contents are ignored, but its length is the count. FetchOp::REPLACE replaces the target value and also returns the pre-update value in result. Concurrent accumulates to one target location must use the same op or MPI_NO_OP, as for accumulate (MPI-4.1 §12.2.1).

The count is origin.len(), and result must be as long as origin; pass sub-slices for a shorter transfer.

§Arguments
  • origin — Local input buffer (read-only).
  • result — Local destination for the pre-update remote value, as long as origin.
  • target_rank — Target rank (0-based, within this window’s communicator).
  • target_disp — Displacement at the target, measured in units of disp_unit (i.e., multiples of size_of::<T>()).
  • op — Reduction operation to apply.
§Errors
  • Error::InvalidArgument with arg: "op" — if op is a predefined op MPI does not define on T (a bitwise or logical op on f32/f64); no MPI call is made.
  • Error::InvalidArgument — if target_rank is not a rank of the window’s communicator (including -1) or of the epoch’s access set (arg: "target_rank"), target_disp is negative, or the access does not fit in the target rank’s window; no MPI call is made.
  • Error::BufferSize with arg: "result" — if result is not as long as origin; no MPI call is made.
  • Error::Finalized — once Mpi is being dropped.
  • Error::Mpi — if MPI_Get_accumulate fails for any other reason; on MPI before 4.0 this includes class Count for an origin of more than i32::MAX elements.
§Example
use ferrompi::{Mpi, ReduceOp, Win, WinFenceAssert};

fn main() -> ferrompi::Result<()> {
    let mpi = Mpi::init()?;
    let world = mpi.world();
    let mut win = Win::<i32>::allocate(&world, 4)?;
    let origin = [1i32, 2, 3, 4];
    let mut result = [0i32; 4];

    // Rank 1 initialises its window
    if world.rank() == 1 {
        win.local().copy_from_slice(&[10, 20, 30, 40]);
    }

    // `origin` and `result` are declared before the epoch: MPI uses them
    // until the closing fence returns
    win.fence(WinFenceAssert::none(), WinFenceAssert::none(), |e| {
        // Rank 0 atomically fetches rank 1's values and adds [1, 2, 3, 4]
        if world.rank() == 0 {
            e.get_accumulate(&origin, &mut result, 1, 0, ReduceOp::Sum)?;
        }
        Ok(())
    })?;

    // The epoch is closed: rank 0 holds the values from before the update,
    // and rank 1's window holds the sums
    if world.rank() == 0 {
        assert_eq!(result, [10, 20, 30, 40]);
    }
    if world.rank() == 1 {
        let mut seen = [0i32; 4];
        win.local().copy_to_slice(&mut seen);
        assert_eq!(seen, [11, 22, 33, 44]);
    }
    Ok(())
}

pub fn fetch_and_op( &self, origin: &'s T, result: &'s mut T, target_rank: i32, target_disp: i64, op: impl Into<FetchOp>, ) -> Result<()>

Single-element atomic fetch-and-update: fetch the pre-update remote value into result, then apply op(origin, target_old) at the target, atomically with respect to other accumulate operations on that location (MPI-4.1 §12.7.1).

Wraps MPI_Fetch_and_op. Restricted to predefined MPI datatypes (no derived or custom datatypes); the T: MpiDatatype bound enforces this at compile time. The operation is posted at once, but result holds the fetched value only after the epoch’s closing call returns, and the update is visible at the target once the target’s own closing call returns. result stays borrowed until then: read it after the closure returns.

op is a ReduceOp, FetchOp::NO_OP (an atomic get, which ignores origin’s value) or FetchOp::REPLACE (a swap); a user op is not accepted (MPI-4.1 §12.3.4). Concurrent accumulates to one target location must use the same op or MPI_NO_OP, as for accumulate (MPI-4.1 §12.2.1).

§Arguments
  • origin — The value to combine with the remote element.
  • result — Local destination for the pre-update remote value.
  • target_rank — Target rank (0-based, within this window’s communicator).
  • target_disp — Displacement at the target, measured in units of disp_unit (i.e., multiples of size_of::<T>()).
  • op — Reduction operation to apply.
§Errors
  • Error::InvalidArgument with arg: "op" — if op is a predefined op MPI does not define on T (a bitwise or logical op on f32/f64); no MPI call is made.
  • Error::InvalidArgument — if target_rank is not a rank of the window’s communicator (including -1) or of the epoch’s access set (arg: "target_rank"), target_disp is negative, or the access does not fit in the target rank’s window; no MPI call is made.
  • Error::Finalized — once Mpi is being dropped.
  • Error::Mpi — if MPI_Fetch_and_op fails for any other reason.

A call refused before MPI runs writes nothing into result, which stays borrowed until the epoch closes. After Error::Mpi, result holds an unspecified value (MPI-4.1 §9.4).

§Example
use ferrompi::{Mpi, ReduceOp, Win, WinFenceAssert};

let mpi = Mpi::init().unwrap();
let world = mpi.world();
let mut win = Win::<i32>::allocate(&world, 1).unwrap();

// Rank 1 initialises its window slot 0 to 100
if world.rank() == 1 {
    win.local().write(0, 100);
}

// `origin` and `old` are declared before the epoch: MPI uses them until
// the closing fence returns
let origin = 1i32;
let mut old = 0i32;
win.fence(WinFenceAssert::none(), WinFenceAssert::none(), |e| {
    // Rank 0 atomically adds 1 to rank 1's slot 0 and fetches the old value
    if world.rank() == 0 {
        e.fetch_and_op(&origin, &mut old, 1, 0, ReduceOp::Sum)?;
    }
    Ok(())
})
.unwrap();

// The epoch is closed: old is now valid
if world.rank() == 0 {
    assert_eq!(old, 100); // pre-update value; rank 1's slot 0 is now 101
}

pub fn compare_and_swap( &self, origin: &'s T, compare: &'s T, result: &'s mut T, target_rank: i32, target_disp: i64, ) -> Result<()>

Single-element atomic compare-and-swap: replace the remote element with origin if it equals compare, and fetch the pre-swap remote value into result.

Wraps MPI_Compare_and_swap. result is always the pre-swap remote value, whether or not the swap happened; the swap happened if result equals compare. The operation is posted at once, but result holds that value only after the epoch’s closing call returns, and the update is visible at the target once the target’s own closing call returns. result stays borrowed until then: read it after the closure returns.

This method exists only for the integer and byte types of AtomicMpiDatatype, the ones MPI-4.1 §12.3.4 allows, so f32 and f64 are excluded.

§Arguments
  • origin — The new value to swap in if compare matches the remote element.
  • compare — The expected current remote value. The swap occurs only if remote_value == compare.
  • result — Local destination for the pre-swap remote value.
  • target_rank — Target rank (0-based, within this window’s communicator).
  • target_disp — Displacement at the target, measured in units of disp_unit (i.e., multiples of size_of::<T>()).
§Errors
  • Error::InvalidArgument — if target_rank is not a rank of the window’s communicator (including -1) or of the epoch’s access set (arg: "target_rank"), target_disp is negative, or the access does not fit in the target rank’s window; no MPI call is made.
  • Error::Finalized — once Mpi is being dropped.
  • Error::Mpi — if MPI_Compare_and_swap fails (for example, the MPI version is below 3).

A call refused before MPI runs writes nothing into result, which stays borrowed until the epoch closes. After Error::Mpi, result holds an unspecified value (MPI-4.1 §9.4).

§Example
use ferrompi::{Mpi, Win, WinFenceAssert};

let mpi = Mpi::init().unwrap();
let world = mpi.world();
let mut win = Win::<i32>::allocate(&world, 1).unwrap();

// Rank 1 initialises its window slot 0 to 100
if world.rank() == 1 {
    win.local().write(0, 100);
}

// `new_value`, `expected` and `old` are declared before the epoch: MPI
// uses them until the closing fence returns
let new_value = 200i32;
let expected = 100i32;
let mut old = 0i32;
win.fence(WinFenceAssert::none(), WinFenceAssert::none(), |e| {
    // Rank 0: swap in 200 only if rank 1's slot 0 is 100
    if world.rank() == 0 {
        e.compare_and_swap(&new_value, &expected, &mut old, 1, 0)?;
    }
    Ok(())
})
.unwrap();

// The epoch is closed: old is now valid
if world.rank() == 0 {
    assert_eq!(old, 100); // pre-swap value; rank 1's slot 0 is now 200
    let swapped = old == expected;
    assert!(swapped);
}
